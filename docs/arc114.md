# ARC114 - Analyze Speech and Language with Google APIs: Challenge Lab

Kembaran [ARC132](../arc132.sh): semua file yang dinilai ada **di dalam VM
`lab-vm`**, bukan di Cloud Shell. Script mengirim satu script remote lewat `scp`
lalu menjalankannya via SSH.

## Jalankan

Bikin API key lewat console dulu (APIs & Services → Credentials → + Create
credentials → API key; kalau diminta API restrictions pilih Cloud Natural
Language API + Cloud Speech-to-Text API, Application restrictions None), lalu:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/arc114.sh
API_KEY=<key-dari-console> bash arc114.sh
```

Tanpa `API_KEY` script bikin key sendiri lewat `gcloud services api-keys create`.
Cukup untuk memanggil API (Task 2-4), tapi di arc132/gsp038/arc130 key buatan
gcloud **tidak** menghijaukan checkpoint "Create an API key".

## Task

| Task | Otomatis | Catatan |
|------|----------|---------|
| 1. Create an API key | Manual | lewat console, seperti [arc132](../arc132.sh) |
| 2. Entity analysis | Ya | `nl_request.json` → `analyzeEntities` → `nl_response.json` |
| 3. Speech analysis | Ya | `speech_request.json` (`gs://cloud-samples-tests/speech/brooklyn.flac`) → `speech:recognize` → `speech_response.json` |
| 4. Sentiment analysis | Ya | melengkapi `analyze()` di `sentiment_analysis.py`, lalu `python3 sentiment_analysis.py reviews/bladerunner-pos.txt` |

## Catatan

- Task 4 tidak menulis ulang `sentiment_analysis.py` mentah-mentah. Script
  mengganti **hanya** fungsi `analyze()` lewat regex, dan mengikuti nama modul
  yang sudah dipakai file lab (`language_v1` atau `language`) supaya cocok dengan
  versi `google-cloud-language` yang terpasang di VM. Kalau signature-nya tidak
  ketemu, barulah file ditulis penuh.
- Sample review diunduh dari `gs://cloud-samples-tests/natural-language/sentiment-samples.tgz`,
  diekstrak ke `reviews/` di direktori yang sama dengan `sentiment_analysis.py`.
- Client library memakai ADC dari service account VM, bukan API key. Kalau Task 4
  gagal autentikasi, cek scope `lab-vm`.
- **Virtualenv di `lab-vm` bernama `env`, bukan `venv`** (arc132 pakai `venv`) —
  dan isinya kosong: `google-cloud-language` belum terpasang, ada `get-pip.py`
  milik root di home sebagai petunjuk lab memang mengharapkan install manual.
  Script sekarang mencari `env`/`venv`/`.venv` lalu `python3 -m pip install
  google-cloud-language` ke dalamnya. Python-nya 3.9.2, jadi ada banjir
  `FutureWarning` dari google-api-core — tidak masalah, hasilnya tetap keluar.
- Script remote sengaja `exit 1` kalau import atau analisis gagal. Sebelumnya
  pakai `set -uo pipefail` tanpa `-e`, jadi Task 4 gagal diam-diam sementara
  penutup tetap mencetak "SELESAI".

## Task 4 tidak berhasil dihijaukan (2026-08-09)

Skor akhir **75/100**. Task 1-3 hijau, Task 4 tetap 0/25 dengan pesan yang sama
setiap kali:

> Please download the samples from the cloud storage URI given in lab and run the
> sentiment analysis on any files present in 'reviews' folder.

Analisisnya sendiri **berhasil** — `Overall Sentiment: score of 0.2 with magnitude
of 4.6` untuk `bladerunner-pos.txt`, dan keempat file di `reviews/` bisa
diproses. Jadi yang gagal bukan kodenya, melainkan apa pun yang dipakai grader
sebagai bukti.

Hipotesis yang **sudah diuji dan gugur** — jangan diulang:

| Hipotesis | Yang dilakukan | Hasil |
|-----------|----------------|-------|
| Library cuma ada di venv | `pip install google-cloud-language` di venv `env` | analisis jalan, checkpoint tetap merah |
| Grader menjalankan script pakai python3 sistem | pasang pip 3.9 + library system-wide (`/usr/local/lib/python3.9/dist-packages`) | `python3 sentiment_analysis.py` jalan tanpa venv, tetap merah |
| Grader memanggil `python`, bukan `python3` | `ln -sf /usr/bin/python3 /usr/bin/python` | tetap merah |
| Grader menghitung request `analyzeSentiment` ber-API-key (seperti Task 2/3) | panggil `documents:analyzeSentiment` via REST + API key atas isi `bladerunner-pos.txt` | tetap merah |
| Grader butuh semua file di `reviews/` diproses | loop keempat file, output di `sentiment_result.txt` | tetap merah |
| `reviews/` mode 750 (dari tarball) tak terbaca user lain | `chmod -R a+rX ~/reviews` | tetap merah |
| Grader baca `~/.bash_history` | perintah lab di-append ke history, lalu diketik manual di SSH console | tetap merah |
| Grader jalan sebagai root, `~` bukan home student | salin `reviews/`, tgz, dan `.py` ke `/root` | tetap merah |
| State instance kadung kotor | unduh ulang tgz dari nol, ekstrak ulang, jalankan manual dari SSH console | tetap merah |

Yang belum diuji dan jadi kandidat pertama kalau lab ini diulang: **jalankan Task
4 lebih dulu, sebelum Task 2 dan 3, di instance yang benar-benar baru** — untuk
memisahkan "grader-nya rewel" dari "urutannya berpengaruh". Kandidat kedua:
checkpoint-nya memang sedang rusak; ARC114 di-update 29 hari sebelum sesi ini.
