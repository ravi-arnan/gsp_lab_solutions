# GSP539 - Build Global and Regional Load Balancing Solutions: Challenge Lab

Runbook untuk [`gsp539.sh`](../gsp539.sh). Status: **belum diuji di lab sungguhan**.

## Kenapa lab ini cocok di-script

Semua task adalah pembuatan resource gcloud murni: MIG, firewall, health check, backend
service, target proxy, forwarding rule, sertifikat, dan satu VM client. Tidak ada wizard
yang harus diklik. Satu-satunya bagian yang lab harapkan dilakukan "manual" adalah melihat
grafik Monitoring saat failover (Task 3) — script tetap melakukan stop/start nginx-nya
lewat SSH, dan grafik bisa dilihat setelahnya.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp539.sh
bash gsp539.sh
```

Script bertanya Region A dan Region B di awal. Kalau VPC `lb-network` dan subnetnya sudah
pre-provisioned (kasus normal), region dan subnet terdeteksi otomatis dan tinggal tekan
ENTER. Region B adalah region yang berisi proxy-only subnet (`10.129.0.0/23`).

Isi lewat env var kalau defaultnya tidak cocok:

```bash
REGION_A=us-west1 REGION_B=us-central1 bash gsp539.sh
```

Idempoten: setiap resource dicek dulu sebelum dibuat, jadi aman dijalankan ulang kalau
gagal di tengah. Kalau instance template `template-proxy-internal` / `template-alb-api`
sudah pre-provisioned, dipakai apa adanya; kalau tidak ada, script membuatnya dengan
startup script nginx.

## Hal yang mudah terlewat / berisiko

- **Region B punya proxy-only subnet.** Regional internal proxy NLB butuh subnet purpose
  `REGIONAL_MANAGED_PROXY` di regionnya. Script mendeteksinya; kalau tidak ada, dibuatkan
  dengan CIDR yang ditanyakan (default `10.129.0.0/23`).
- **VIP internal harus `--purpose=SHARED_LOADBALANCER_VIP`**, bukan `GCE_ENDPOINT`.
  Kalau salah, forwarding rule akan menolak.
- **Firewall health check internal: `35.191.0.0/16` saja.** Untuk load balancer berbasis
  Envoy (internal proxy NLB), prober hanya datang dari range itu — bukan
  `130.211.0.0/22` (itu hanya untuk LB berbasis GFE). Range ini yang dipakai dokumentasi
  resmi regional internal proxy NLB. Kalau checkpoint Task 1 tetap tidak hijau, ini hal
  pertama yang dicurigai.
- **Firewall ALB global: kedua range.** Global external ALB pakai GFE, jadi health check
  datang dari `130.211.0.0/22` dan `35.191.0.0/16`.
- **Named port lewat `set-named-ports`, bukan flag saat create MIG.** `gcloud compute
  instance-groups managed create` tidak punya flag named ports.
- **Max RPS 1 adalah total per backend group**, bukan per instance (`--max-rate=1`, bukan
  `--max-rate-per-instance=1`). Ini yang membuat traffic meluas ke region kedua saat
  diuji. Kalau checkpoint Task 2/3 komplain, coba ganti ke `--max-rate-per-instance=1`.
- **MIG sengaja size=1** supaya stop nginx di satu instance = satu region mati total dan
  failover terlihat. Kalau size 2, region A masih sehat saat satu instance dihentikan.
- **Validasi Task 1 butuh SSH ke client VM.** `gcloud compute ssh` dari Cloud Shell butuh
  firewall `allow-ssh` (dibuatkan script kalau belum ada). Kalau SSH gagal, script
  mencetak perintah manualnya.
- **Client VM harus satu region dengan LB internal** (Region B). Internal LB tanpa global
  access hanya menerima trafik dari sumber di region yang sama.
