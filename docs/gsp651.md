# GSP651 - Setting Up Cost Control with Quota

Runbook untuk [`gsp651.sh`](../gsp651.sh).

Lab ini mendemonstrasikan pengendalian biaya kueri BigQuery on-demand dengan menetapkan batas kuota (custom quota override) menggunakan perintah `gcloud alpha services quota update`. Praktik ini mencegah pengeluaran biaya tak terduga dari kueri besar dengan membatasi volume pemrosesan data harian per pengguna.

## Cara jalan

Jalankan perintah one-liner langsung di terminal Cloud Shell:

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp651.sh | bash
```

Atau unduh terlebih dahulu lalu jalankan:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp651.sh
bash gsp651.sh
```

Durasi eksekusi: sekitar 1 sampai 2 menit.

## Yang Perlu Diperhatikan

1. **Lokasi Multi-Region Dataset Publik:**
   Dataset publik `bigquery-public-data` bertempat di multi-region `US`. Pemanggilan `bq query` menyertakan `--location="US"` untuk menjamin kompatibilitas pemrosesan kueri.

2. **Unit Metrik Kuota Service Usage (MiBy):**
   Metrik `bigquery.googleapis.com/quota/query/usage` menggunakan satuan MiBy (Mebibytes). Nilai `262144` ekuivalen dengan `256 GiB` atau `0.25 TiB` per hari per pengguna dalam satu project (`unit: 1/d/{project}/{user}`).

3. **Perilaku Query Cache:**
   BigQuery secara default meng-cache hasil kueri tanpa biaya tambahan dan tidak memotong kuota. Penonaktifan cache (`--nouse_cache`) diperlukan agar evaluasi kueri memproses data aktual dan tertahan oleh batas kuota yang baru disetel.
