# GSP319 - Build a Website on Google Cloud: Challenge Lab

Runbook untuk [`gsp319.sh`](../gsp319.sh). Status: **terverifikasi 100/100 (2026-08-10)**,
sekali jalan tanpa intervensi.

Lab-nya versi challenge dari codelab
[monolith-to-microservices](https://github.com/googlecodelabs/monolith-to-microservices):
build monolith jadi container, taruh di GKE, lalu pecah jadi tiga microservice
(orders, products, frontend).

## Sebelum jalan

1. Start lab, login pakai kredensial student, buka Cloud Shell.
2. **Catat lima nilai acak dari halaman lab.** Angkanya beda tiap peserta:

   | Yang ditanya script | Contoh di soal |

   | `CLUSTER` | `fancy-prod-910` |

   | `ORDERS` | `fancy-orders-432` |
   | `PRODUCTS` | `fancy-products-402` |
   | `FRONTEND` | `fancy-frontend-675` |
   | `ZONE` | `us-central1-a` |

## Jalankan

Jangan di-pipe ke `bash` kalau nilainya beda dari default — pertanyaan hanya muncul
kalau stdin terminal.

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp319.sh
bash gsp319.sh
```

Atau isi lewat env var sekaligus:

```bash
CLUSTER=fancy-prod-910 MONOLITH=fancy-monolith-916 ORDERS=fancy-orders-432 \
PRODUCTS=fancy-products-402 FRONTEND=fancy-frontend-675 bash gsp319.sh
```

Durasi **20–25 menit**. Yang lama: `setup.sh` (npm install tiga proyek + build
React, ~5 menit), empat kali Cloud Build (~2 menit masing-masing), dan cluster GKE
(~5 menit). Cluster dibuat di latar belakang sambil build monolith jalan, jadi dua
antrean panjang itu tumpang tindih. Build orders dan products juga paralel.

## Kenapa `.env` ditulis ulang, bukan di-`sed`

`npm run build` di `react-app` punya `prebuild` (build versi monolith pakai
`.env.monolith`) dan `postbuild` (menyalin hasil ke
`microservices/src/frontend/public`). Jadi cukup satu `npm run build`; image
frontend otomatis membawa URL baru. File `.env` aslinya tanpa newline di akhir,
menulis ulang seluruh file lebih aman daripada `sed` in-place.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `Timeout menunggu external IP service X` | LoadBalancer belum dapat IP setelah 10 menit. Cek `kubectl get svc`, biasanya kuota atau service terlanjur dibuat dengan tipe salah — `kubectl delete svc X` lalu jalankan ulang script. |
| Frontend tampil tapi Products/Orders kosong | Image frontend membawa URL lama. Script sudah menghapus image lama dan memasang `imagePullPolicy: Always`, tapi kalau masih terjadi: `kubectl delete deployment <frontend>` lalu jalankan ulang. |
| `denied: Permission ... artifactregistry` saat build | Cloud Build SA belum punya izin tulis. Jarang di lab ini; kalau muncul, beri `roles/artifactregistry.writer` ke `<PROJECT_NUMBER>@cloudbuild.gserviceaccount.com`. |
| `npm run build` gagal soal OpenSSL | Versi node terlalu baru untuk react-scripts. `nvm install --lts` sudah dijalankan script; kalau tetap gagal, `export NODE_OPTIONS=--openssl-legacy-provider` lalu ulangi. |
| Berhenti di tengah | `set -e`, baris terakhir output adalah penyebabnya. Script idempoten: image yang sudah ada dilewati, cluster/deployment/service yang sudah ada tidak dibuat ulang. Aman diulang dari awal. |

panggilan `gcloud`/`kubectl` keluar dengan urutan dan flag yang benar sampai banner
penutup.
