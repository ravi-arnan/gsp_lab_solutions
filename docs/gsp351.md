# GSP351 - Migrate MySQL Data to Cloud SQL Using Database Migration Service: Challenge Lab

Runbook untuk [`gsp351.sh`](../gsp351.sh). Status: terverifikasi 100/100 (2026-08-22, us-central1).

Lab terpanjang di repo ini sejauh ini: dua migrasi DMS penuh, masing-masing dump
dan restore database 5030 baris.

## Sebelum jalan

Start lab, login student, buka Cloud Shell. Tidak ada parameter — nama VM sumber
dan kedua Cloud SQL punya suffix acak per instance dan ditemukan sendiri oleh
script. Kredensial source tetap `admin` / `changeme`.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp351.sh
bash gsp351.sh                 # Task 1-4, 15-25 menit
# klik Check my progress 1-4 sampai hijau
bash gsp351.sh promote         # Task 5, 3-5 menit
```

## Yang dikerjakan script

| Task | Aksi | Checkpoint |
|------|------|------------|
| 1 | connection profile source: `--host=<external IP dev-mkt-*>`, `--port=3306`, admin/changeme | ✅ Connection profile |
| — | dua profile destination dengan `--cloudsql-instance` (setara "Existing instance" di console) | — |
| 2 | job `--type=ONE_TIME --static-ip`, demote destination, start, tunggu `COMPLETED` | ✅ One-time migration |
| 3 | job `--type=CONTINUOUS --peer-vpc=projects/<PROJECT>/global/networks/default`, demote, start, tunggu `RUNNING` | ✅ Continuous migration |
| 4 | `update customers set gender='FEMALE' where addressKey=934` di source, tunggu 90 detik | ✅ Replikasi perubahan |
| 5 | `migration-jobs promote`, tunggu `instanceType` jadi `CLOUD_SQL_INSTANCE` | ✅ Promote |

`--static-ip` adalah terjemahan CLI dari connectivity **IP allowlist** di console —
cara DMS memakai external IP source. Firewall `default-allow-mysql` bawaan lab
sudah membuka 3306, jadi tidak perlu rule tambahan.

## Tiga jebakan yang ditemukan saat jalan perdana

### 1. Destination berupa instance existing wajib di-demote dulu

```
FAILED_PRECONDITION: Destination has to be demoted in order to be able to
start/verify the migration.
```

Di console, memilih **Existing instance** diam-diam men-demote instance itu jadi
replica. Lewat CLI langkahnya harus eksplisit, di antara `create` dan `start`:

```bash
gcloud database-migration migration-jobs demote-destination <job> --region=<region>
```

Operasinya asinkron. Tunggu sampai `gcloud sql instances describe <inst>
--format='value(instanceType)'` berbunyi `READ_REPLICA_INSTANCE` sebelum `start`.

### 2. Demote membuat instance `<destination>-master` yang bukan database

`demote-destination` membuat *source representation instance* bernama
`mysql-mkt-<xxx>-master`. Isinya cuma metadata; statusnya tidak pernah
`RUNNABLE`. Deteksi otomatis yang cuma mengecualikan `-cont` akan salah memilih
instance ini dan `migration-jobs create` menolak dengan:

```
FAILED_PRECONDITION: Instance must be in the RUNNABLE state
```

Filter di script mengecualikan `-cont` **dan** `-master`.

### 3. Hanya `create` yang punya `--no-async`

`migration-jobs start` dan `migration-jobs promote` menolak flag itu
(`unrecognized arguments: --no-async`). Keduanya asinkron dan hasilnya dipantau
sendiri:

- `start` → pantau `migration-jobs describe --format='value(state)'` sampai
  `COMPLETED` (one-time) atau `RUNNING` (continuous).
- `promote` → pantau sampai `state` `COMPLETED`; `phase` sempat lama di
  `PROMOTE_IN_PROGRESS`, dan `instanceType` bisa sudah `CLOUD_SQL_INSTANCE`
  sementara job-nya belum selesai. Yang menentukan checkpoint adalah job-nya.

Versi awal script menelan error `start` dengan `|| true`, akibatnya loop memantau
`NOT_STARTED` selama 25 menit tanpa sebab yang terlihat. Sekarang errornya
dicetak, dan loop menyerah setelah satu menit kalau state tidak beranjak dari
`NOT_STARTED`.

## Kenapa dua fase

`promote` menghentikan replikasi. Kalau dijalankan sebelum checkpoint 4 diklik,
tidak ada lagi job berstatus `Running` yang bisa dilihat grader.

## Verifikasi manual

```bash
gcloud sql connect <instance-one-time> --user=root
use customers_data; select count(*) from customers;   -- harus 5030
```

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `Destination has to be demoted` | Lihat jebakan 1. |
| `Instance must be in the RUNNABLE state` | Target salah tertuju ke instance `-master`. Lihat jebakan 2. |
| `unrecognized arguments: --no-async` | Flag itu hanya milik `create`. Lihat jebakan 3. |
| State mandek di `NOT_STARTED` | `start` gagal atau tidak pernah dipanggil. Jalankan manual `migration-jobs start <job> --region=<region>`. |
| Job `FAILED` | Script mencetak blok `error` dari `describe`. Sering karena source belum bisa dihubungi; cek firewall 3306 dan external IP di connection profile. |
