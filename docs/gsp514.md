# GSP514 - Build a Data Mesh with Knowledge Catalog: Challenge Lab

Runbook untuk [`gsp514.sh`](../gsp514.sh). Status: terverifikasi di us-east4 (2026-07-17). Task 2b harus dikerjakan lewat UI, lihat di bawah.

## Peringatan utama

**Challenge lab, tapi tasknya tidak diacak.** Beda dengan GSP340, halaman lab ini tidak memuat `Dynamically selected task`. Kelima task-nya tetap. Yang berubah per instance cuma **region**, **project**, dan **email User 2**.

**Task 2b harus lewat UI.** Aspect ditempel ke **zone**, bukan tabel BigQuery seperti GSP1145. Asumsi awal adalah zone muncul sebagai entry di entry group `@dataplex`. **Itu salah.** Diagnostik di lab sungguhan menunjukkan `@dataplex` hanya berisi entry untuk metadata resource (aspect type), dan tidak ada zone di dalamnya:

```
$ gcloud dataplex entries list --entry-group=@dataplex --location=us-east4 --format='value(name)'
protected-customer-data-aspect_aspectType
@dataplex_entry
```

Entry group itu bahkan baru dibuat pada detik yang sama dengan aspect type. Menunggu lebih lama tidak menolong. Script tetap mencoba mencari entry-nya (murah dan non-fatal), lalu melewati Task 2b dengan peringatan dan lanjut ke Task 3-5. Kerjakan Task 2b lewat UI, enam klik, lihat bagian bawah.

**Lab 45 menit tapi datascan butuh beberapa menit.** Jalankan script lebih awal, checkpoint Task 5 baru hijau setelah job-nya `SUCCEEDED`.

## Keputusan yang perlu kamu tahu

**Task 3 pakai `roles/dataplex.dataWriter`.** Lab minta "principle of least privilege" untuk upload file. `dataReader` tidak bisa upload, sedangkan `dataOwner` dan `admin` kelebihan hak. Writer adalah yang terkecil yang cukup.

**`threshold: 1`, bukan `100`.** Spec data quality memakai rasio 0 sampai 1, jadi 100% ditulis `1`. Ini gampang salah.

**`resultsTable` pakai prefix `//bigquery.googleapis.com/`.** Dokumentasi menampilkan dua format (`projects/...` dan `//bigquery.googleapis.com/projects/...`) dan bilang keduanya valid. Script memakai yang berprefix karena itu yang direkomendasikan panduan REST.

**Service account = Compute Engine default**, dihitung dari nomor project: `<PROJECT_NUMBER>-compute@developer.gserviceaccount.com`.

**Prasyarat tersembunyi Task 5.** Dataplex menjalankan datascan dengan cara **meng-impersonate** compute SA, jadi Dataplex service agent (`service-<PROJECT_NUMBER>@gcp-sa-dataplex.iam.gserviceaccount.com`) butuh `roles/iam.serviceAccountTokenCreator` pada compute SA. Tanpa itu, `datascans create` gagal 403 `does not have permission to impersonate`. Prasyarat ini **tidak disebut di halaman lab maupun di dokumentasi `gcloud dataplex datascans`**. Kalau lewat console, UI yang diam-diam mengurusnya, makanya jalur CLI kena dan jalur klik tidak. Script sudah memasangnya.

**IAM butuh waktu menyebar.** Binding di atas tidak langsung aktif. Memanggil `datascans create` sedetik setelah grant tetap menghasilkan 403 walau binding-nya sudah benar. Script menunggu 20 detik lalu mencoba ulang sampai 6 kali.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `bucket pre-created belum lengkap` | Provisioning lab belum selesai. Script mencetak daftar bucket yang ada. Tunggu, jalankan ulang. |
| `entry zone tidak ketemu di entry group @dataplex` | **Diharapkan.** Zone memang tidak ada di `@dataplex`. Jangan buang waktu menunggu. Script melewatinya dan lanjut ke Task 3-5. Kerjakan Task 2b lewat UI. |
| Datascan job `FAILED` | Cek service account punya akses ke dataset sumber dan dataset hasil. Cek juga `orders_dq_dataset` memang ada. |
| Checkpoint Task 5 merah | Job belum selesai. Cek `datascans jobs list`, tunggu `SUCCEEDED`, klik lagi. |
| `403 does not have permission to impersonate` | Propagasi IAM. Binding-nya sudah benar tapi belum menyebar. Script otomatis menunggu dan mencoba ulang sampai ~2 menit. Kalau tetap gagal, cek `gcloud iam service-accounts get-iam-policy <compute-sa>`. |
| `NOT_FOUND` di mana pun | Region salah. Cocokkan dengan kalimat region di halaman lab. |

## Task 2b lewat UI (wajib, bukan opsional)

Script mengerjakan Task 2a (aspect type-nya), jadi tinggal pilih dari daftar:

1. Knowledge Catalog > Discover > Search.
2. Cari `Raw Customer Zone`, klik hasilnya.
3. Scroll ke **Aspects**, di sebelah **Optional aspects** klik **Add**.
4. Pilih **Protected Customer Data Aspect**.
5. Isi **Raw Data Flag** = Yes dan **Protected Contact Information Flag** = Yes.
6. **Save**.
