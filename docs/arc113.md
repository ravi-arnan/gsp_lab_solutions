# ARC113 - Implement Event-Driven Messaging and Automation Workflows: Challenge Lab

Runbook untuk [`arc113.sh`](../arc113.sh). Status: **terverifikasi 100/100** (2026-08-10), sekali jalan tanpa intervensi, varian schema + topic + Cloud Run function.

## Peringatan: lab ini punya beberapa varian task

Deskripsi lab menyebut sendiri "you **may** get task to use Cloud Scheduler ... In addition to that, you **may** get task to create Pub/Sub Schema, Snapshot and need to setup the Pub/Sub Lite". Task yang muncul berbeda antar-instance.

Script ini mengerjakan varian **schema + topic + Cloud Run function**:

| Task | Cara |
|------|------|
| 1 Schema `city-temp-schema` | `gcloud pubsub schemas create --type=AVRO` |
| 2 Topic `temp-topic` pakai schema `temperature-schema` (pre-created) | `gcloud pubsub topics create --schema=... --message-encoding=json` |
| 3 Function `gcf-pubsub` dipicu topic `gcf-topic` | `gcloud functions deploy --gen2 --trigger-topic` |

Nama resource bisa diganti lewat env var kalau panel lab menyebut yang lain:

```bash
SCHEMA_NEW=... SCHEMA_EXISTING=... TOPIC=... GCF_TOPIC=... FUNCTION=... REGION=... bash arc113.sh
```

Varian lain (Cloud Scheduler cron job, snapshot, Pub/Sub Lite) belum ditulis. Perintah intinya kalau muncul:

```bash
gcloud scheduler jobs create pubsub <JOB> --schedule="* * * * *" --topic=<TOPIC> \
  --message-body="<BODY>" --location=<REGION>
gcloud pubsub snapshots create <SNAP> --subscription=<SUB>
gcloud pubsub lite-topics create <TOPIC> --location=<ZONE> --partitions=1 \
  --per-partition-bytes=30GiB
```

## Yang tidak disebut instruksi lab

### "Cloud Run Function environment" = gen2

Task 3 menyebut "the Cloud Run Function environment". Itu `--gen2`, bukan Cloud Functions generasi lama. Tanpa flag itu checkpoint bisa merah walau function-nya jalan.

### IAM diberikan di depan

Deploy gen2 pertama di project baru sering gagal karena service agent Eventarc/Pub/Sub belum punya role. Script mengikat lebih dulu ke default compute SA: `eventarc.eventReceiver`, `run.invoker`, `artifactregistry.reader`, plus `iam.serviceAccountTokenCreator` untuk service agent Pub/Sub. Deploy tetap diulang sampai 3 kali dengan jeda 30 detik untuk propagasi.

### Schema tidak bisa ditempel ke topic yang sudah ada

`schemaSettings` hanya bisa diisi saat topic dibuat. Kalau `temp-topic` sudah ada tanpa schema (mis. sisa percobaan sebelumnya), script menghapus dan membuatnya ulang, bukan mencoba `topics update` yang tidak menyediakan field itu.

## Idempoten

Aman diulang: schema dan topic dilewati kalau sudah benar, function di-deploy ulang di tempat.
