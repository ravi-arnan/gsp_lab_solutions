# GSP091 - Creating and Alerting on Logs-based Metrics

Runbook untuk [`gsp091.sh`](../gsp091.sh). Status: siap dijalankan di Cloud Shell.

## Ringkasan Lab

Lab ini mempelajari pembuatan dan pemanfaatan **Logs-based Metrics** serta konfigurasi kebijakan peringatan (**Alerting Policies**) berbasis log dan metrik di Google Cloud Observability (Cloud Logging dan Cloud Monitoring).

Arsitektur terdiri dari:
1. **GKE Cluster (`gmp-cluster`)**: Cluster Kubernetes 1-node sebagai host aplikasi backend demo.
2. **Log-based Alert (`stopped vm`)**: Kebijakan peringatan instan yang mendeteksi event penghentian VM (`v1.compute.instances.stop`) di audit logs Compute Engine.
3. **Artifact Registry (`docker-repo`)**: Repository Docker pribadi untuk menyimpan container image `flask-telemetry:v1`.
4. **Flask Application (`hello`)**: Service web di namespace `gmp-test` yang mengekspos endpoint `/metrics` dan `/error` melalui Kubernetes Service bertipe LoadBalancer.
5. **Log-based Metric (`hello-app-error`)**: Metrik user-defined tipe Counter yang mengekstrak log error 404 dari container `hello-app`.
6. **Metrics-based Alert (`log based metric alert`)**: Kebijakan peringatan ambang batas (threshold alert) yang memantau kenaikan metrik `logging.googleapis.com/user/hello-app-error`.

```bash

```

Zona akan ditanyakan di awal (default `europe-west4-b`). Tekan `Enter` jika panel lab Anda menggunakan zona tersebut, atau ketik sesuai panel lab Anda.

## Checkpoint yang Dinilai

| Task | Checkpoint | Otomatis | Keterangan |
|------|------------|:--------:|------------|
| 1 | Deploy the GKE cluster | Ya | Membuat GKE cluster `gmp-cluster` (1 node) |
| 2 | Create the Log-based alert | Ya | Membuat notification channel dan alert policy `stopped vm`, lalu menghentikan `instance1` |
| 3 | Create a Docker repository | Ya | Membuat Artifact Registry `docker-repo` dan push image `flask-telemetry:v1` |
| 4 | Deploy the simple application that emits metrics | Ya | Deploy deployment dan LoadBalancer service `hello` di namespace `gmp-test` |
| 5 | Create the log-based metric | Ya | Membuat user-defined metric `hello-app-error` dengan filter error 404 container `hello-app` |
| 6 | Create the metrics-based alert | Ya | Membuat alert policy `log based metric alert` berbasis metric threshold 120s |
| 7 | Generate some errors | Ya | Mengirim request HTTP ke `/error` secara otomatis untuk menaikkan counter metrik |

Total: **100/100 poin** otomatis (7/7 checkpoint).

## Detail Teknis & Penanganan Otomasi

- **Otomasi Log-based Alert**: Kebijakan `stopped vm` dibuat menggunakan skema JSON `conditionMatchedLog` dengan `autoClose` 1 jam dan rate limit 5 menit, dipadukan dengan penghentian `instance1` secara otomatis untuk trigger entri log.
- **Docker Push ke Artifact Registry**: Script mengonfigurasi autentikasi docker gcloud secara otomatis (`gcloud auth configure-docker`) sebelum push image hasil unzip.
- **Validasi Rollout LoadBalancer**: Loop polling memastikan External IP service `hello` teralokasi sebelum beralih ke tahap pembangkitan error HTTP.
