# ARC106 - Streaming Analytics into BigQuery: Challenge Lab

Runbook untuk [`arc106.sh`](../arc106.sh). Status: skor 100/100 terverifikasi
lewat referensi solusi komunitas (Gaston-MaikMax/arcade → TechCode.sh dari

## Kenapa lab ini cocok di-script

Kelima task semuanya berbasis gcloud/bq/gsutil CLI (bucket, BigQuery, Pub/Sub,
Dataflow). Tidak ada checkpoint murni UI.

## Sebelum jalan

1. Start lab, login pakai kredensial student, buka Cloud Shell.
2. Salin nilai random di halaman lab: region, nama dataset, nama tabel, nama
   topic, nama job (contoh varian: `us-east4`, `sensors_208`,
   `temperature_641`, `sensors-temp-77310`, `dfjob-93262`).
3. Sediakan 10-20 menit. Provisioning Dataflow yang paling lama.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/arc106.sh
```

## Detail task

### Task 1: Bucket

```bash
gsutil mb gs://$PROJECT_ID
```

### Task 2: Dataset dan tabel

```bash
bq --project_id=$PROJECT_ID mk -d $DATASET
bq --project_id=$PROJECT_ID mk --table $PROJECT_ID:$DATASET.$TABLE data:string
```

### Task 3: Topic Pub/Sub

```bash
gcloud pubsub topics create $TOPIC
gcloud pubsub subscriptions create $TOPIC-sub --topic=$TOPIC
```

### Task 4: Pipeline Dataflow

Dua template di-luncurkan supaya alurnya sama dengan solusi yang sudah terbukti:

1. Flex template:

```bash
gcloud dataflow flex-template run $JOB --region=$REGION \
  --template-file-gcs-location gs://dataflow-templates-$REGION/latest/flex/PubSub_to_BigQuery_Flex \
  --temp-location gs://$PROJECT_ID/temp/ \
  --parameters outputTableSpec=$PROJECT_ID:$DATASET.$TABLE,inputTopic=projects/$PROJECT_ID/topics/$TOPIC,outputDeadletterTable=$PROJECT_ID:$DATASET.$TABLE,javascriptTextTransformReloadIntervalMinutes=0
```

2. Template klasik:

```bash
gcloud dataflow jobs run ${JOB}-techcode \
  --gcs-location gs://dataflow-templates-$REGION/latest/PubSub_to_BigQuery \
  --region=$REGION --staging-location gs://$PROJECT_ID/temp \
  --parameters inputTopic=projects/$PROJECT_ID/topics/$TOPIC,outputTableSpec=$PROJECT_ID:$DATASET.$TABLE
```

Script menunggu tiap job sampai state `Running` (maksimal 12 menit) sebelum
meneruskan, karena pesan yang di-publish sebelum job jalan tidak masuk tabel.

### Task 5: Pesan dan validasi

```bash
gcloud pubsub topics publish $TOPIC --message='{"data": "73.4 F"}'
bq query --nouse_legacy_sql "SELECT * FROM \`$PROJECT_ID.$DATASET.$TABLE\`"
```

## Checkpoint

- Task 1: Create a Cloud Storage bucket
- Task 2: Create a BigQuery dataset and table
- Task 3: Set up a Pub/Sub topic
- Task 4: Run a Dataflow pipeline (Pub/Sub → BigQuery)
- Task 5: Publish a test message and validate data in BigQuery

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Job Dataflow gagal sebelum sempat naik | Dataflow API perlu di-restart. Script melakukannya di awal (disable + enable) selama belum ada job aktif; kalau tetap gagal, cek log job di Console. |
| `template not found` saat run job | Template GCS dependen region (`gs://dataflow-templates-$REGION/...`). Pastikan REGION cocok dengan panel lab; sebagian region memakai template di region terdekat. |
| Job stuck `Queued` lama | Provisioning streaming memang lambat. Tunggu saja; pesan yang di-publish menunggu job up. |
| Tabel kosong setelah query | Pesan di-publish sebelum job `Running`. Script menunggu state-nya, tetapi kalau tetap kosong tunggu 1-2 menit lalu publish manual: `gcloud pubsub topics publish $TOPIC --message='{"data": "73.4 F"}'`. |
| `bq` bilang resource sudah ada | Idempoten, skip otomatis. |
