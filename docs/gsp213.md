# GSP213 - Control Access to VPC Networks Using Firewall Rules and IAM

Runbook untuk [`gsp213.sh`](../gsp213.sh).

Lab ini mendemonstrasikan implementasi keamanan jaringan di Google Cloud VPC dengan membuat dua instance web server Nginx (`blue` dengan network tag `web-server` dan `green` tanpa tag), tagged firewall rule untuk ingress port 80 HTTP, instance `test-vm` untuk verifikasi konektivitas internal VPC, serta konfigurasi IAM role `Compute Network Admin` dan `Compute Security Admin` pada service account `network-admin`.

## Cara jalan

Jalankan perintah one-liner langsung di terminal Cloud Shell:

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp213.sh | bash
```

Atau unduh terlebih dahulu dan jalankan:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp213.sh
bash gsp213.sh
```

Durasi eksekusi: sekitar 2 sampai 4 menit (termasuk waktu boot VM dan eksekusi startup script Nginx).

## Yang Perlu Diperhatikan

1. **Tagged Firewall Rule Filtering:**
   Server `blue` menerima traffic HTTP publik dari internet karena memiliki network tag `web-server` yang cocok dengan target firewall rule `allow-http-web-server`. Server `green` tidak memiliki tag tersebut, sehingga akses HTTP eksternal diblokir, namun tetap dapat diakses dari dalam VPC melalui `test-vm` (diizinkan oleh rule bawaan `default-allow-internal`).

2. **Pertahankan Firewall Rule dan IAM Role:**
   Pada simulasi di Task 3, instruksi lab menunjukkan proses penghapusan firewall rule menggunakan hak akses Security Admin. Dalam script otomasi, firewall rule `allow-http-web-server` dan role IAM sengaja dipertahankan agar seluruh 6 checkpoint verifikasi di grader Cloud Skills Boost tetap bernilai hijau.

3. **Startup Script Polling:**
   Script menyertakan loop pengecekan HTTP sederhana ke IP eksternal server `blue` untuk memastikan service Nginx sudah aktif dan menyajikan halaman sebelum proses otomasi selesai.
