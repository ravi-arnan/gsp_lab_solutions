Lab ini sepenuhnya CLI — tidak ada satu pun langkah Console, jadi satu script menutup kedelapan checkpoint.

## Jalankan


## Yang tidak disalin mentah dari instruksi lab

- **Nama rollout prod diambil dari API, bukan ditebak.** Lab menuliskan `web-app-001-to-prod-0001` secara harfiah. Nomor urutnya bertambah kalau promote pernah diulang, jadi script mencarinya lewat `rollouts list --filter="targetId=prod AND state=PENDING_APPROVAL"`.
- **Semua perintah interaktif dipaksa `-q`.** `releases promote` dan `rollouts approve` bertanya konfirmasi; tanpa `-q` script menggantung.
- **Cluster dibuat `--async` lalu ditunggu di Task 6**, persis pola lab. Yang penting jangan membuat target sebelum ketiganya `RUNNING`.
- **`--region` ditulis eksplisit di tiap perintah `gcloud beta deploy`** walau `deploy/region` sudah di-set, supaya tidak bergantung pada config yang bisa tergeser.
- Bucket `<PROJECT_ID>_cloudbuild` namanya global; kegagalan "sudah ada" diabaikan.

## Polling

Rollout pertama lama karena Cloud Deploy me-render manifest untuk **semua** target sekaligus saat release dibuat, bukan saat promote. Script menunggu tiap rollout sampai `SUCCEEDED` (maksimal 30 menit per target) sebelum lanjut promote — kalau promote dijalankan sebelum rollout sebelumnya selesai, perintahnya ditolak.

Nilai state di API adalah `SUCCEEDED`. Contoh output di teks lab menampilkan `SUCCESS` di satu tempat dan `SUCCEEDED` di tempat lain; script menerima keduanya.

## Idempoten

Aman diulang. Cluster, repository, release, dan rollout dicek dulu sebelum dibuat; `skaffold build` dilewati kalau `web/artifacts.json` sudah ada; `deploy apply` untuk pipeline dan target memang sudah idempoten secara desain.

Kalau ingin membangun ulang image dari nol, hapus `~/cloud-deploy-tutorials/tutorials/base/web/artifacts.json` sebelum menjalankan lagi.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `skaffold: command not found` | Cloud Shell biasanya sudah punya skaffold. Kalau tidak, `gcloud components install skaffold`. |
| Cluster lama sekali `PROVISIONING` | Normal, 5-7 menit untuk tiga cluster regional. Script menunggu sendiri. |
| `Unable to get target test/staging/prod` saat Task 5 | Diharapkan. Pipeline dibuat sebelum targetnya ada. |
| Rollout `FAILED` di test | Namespace `web-app` belum ada di cluster itu. Jalankan ulang script (idempoten). |
| Promote ditolak | Rollout sebelumnya belum `SUCCEEDED`. Script sudah menunggu; kalau muncul manual, tunggu lalu ulangi. |
| Rollout prod tidak masuk `PENDING_APPROVAL` | Cek `requireApproval: true` ada di `clouddeploy-config/target-prod.yaml`. |
