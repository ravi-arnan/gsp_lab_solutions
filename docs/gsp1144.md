# GSP1144 - Knowledge Catalog: Qwik Start - Command Line

Runbook untuk [`gsp1144.sh`](../gsp1144.sh). Status: terverifikasi 100/100 (2026-08-06), region `us-east1`.

Versi command line dari [GSP1143](gsp1143.md). Struktur labnya identik (lake → zone → asset → hapus semua), bedanya cuma nama resource dan asetnya BigQuery dataset, bukan bucket.

## Peringatan utama

**Script ini dua fase, jangan digabung.** Task 4 menghapus lake, zone, dan asset yang dibuat Task 1 sampai 3. Kalau create dan delete dijalankan sekaligus, checkpoint task 1-3 gagal karena resource-nya sudah lenyap saat kamu klik Check my progress. Skor nyangkut di 25/100.

**Region di lab ini tetap `us-east1`** (ditulis eksplisit di bagian setup, tidak diacak per instance). Kalau halaman lab-mu menyebut region lain, override lewat env var.

## Sebelum jalan

1. Start lab, login akun student, buka Cloud Shell.
2. Enable Dataplex API sudah ditangani script, tidak perlu manual.

## Jalankan

Download dulu, jangan pipe ke bash. `curl ... | bash -s create` membuat script dan stdin berebut, dan filenya tetap dibutuhkan untuk fase kedua.

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp1144.sh
```

**Fase 1** (Task 1, 2, 3):

```bash
bash gsp1144.sh create
```

**Fase 2**: klik **Check my progress** untuk task 1, 2, dan 3 sampai **hijau semua**. Jangan lompat.

**Fase 3** (Task 4):

```bash
bash gsp1144.sh delete
```

Lalu klik Check my progress untuk task 4.

Lake butuh sampai 3 menit, zone dan asset masing-masing sampai 2 menit. gcloud menunggu sampai selesai, jadi terlihat diam cukup lama. Itu normal.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Checkpoint task 1-3 merah setelah delete | Kamu menjalankan `delete` sebelum checkpoint hijau. Jalankan `create` lagi, klik checkpoint dulu, baru `delete`. |
| `Status code: 403 ... dataplex.lakes.create denied` | Propagasi permission setelah API di-enable belum selesai. Tunggu 1-2 menit, jalankan ulang fase `create` (idempoten). |
| `NOT_FOUND` saat delete | Region salah. Cek `gcloud dataplex lakes list --location=<region>`. |
| Dataset gagal dibuat karena location | Dataset BigQuery harus se-region dengan lake. Jangan campur region antar fase. |

## Catatan

Detach asset **tidak** menghapus dataset BigQuery-nya. Setelah fase delete, dataset `orders` masih ada di project; yang dilepas cuma pendaftarannya di zone. Itu memang perilaku yang benar menurut labnya.
