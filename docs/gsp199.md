# GSP199 - Service Accounts and Roles: Fundamentals

Runbook untuk [`gsp199.sh`](../gsp199.sh). Status: **siap uji**.

Lab fundamental tentang pembuatan service account, pemberian IAM roles, asosiasi service account dengan Compute Engine VM instance, dan akses BigQuery public dataset melalui Python client library.

## Alur Kerja

1. **Task 1: Create and manage service accounts**
   - Membuat service account `my-sa-123`.
   - Mengikat role `roles/storage.admin` ke service account tersebut di level project.
   - Penilaian: *Create and Manage Service Accounts* (50 pts).

2. **Task 2: Use client libraries to access BigQuery using a service account**
   - Membuat service account `bigquery-qwiklab`.
   - Memberikan role `roles/bigquery.dataViewer` dan `roles/bigquery.user` ke `bigquery-qwiklab`.
   - Membuat VM instance `bigquery-instance` (Debian 12, `e2-medium`) yang diasosiasikan dengan service account `bigquery-qwiklab` dan access scopes BigQuery.
   - Menginstal dependensi Python (`google-cloud-bigquery`, `pyarrow`, `pandas`, `db-dtypes`) di VM.
   - Menjalankan `query.py` yang mengeksekusi kueri dataset publik `publicdata.samples.natality` via service account credentials.
   - Penilaian: *Access BigQuery using a Service Account* (50 pts).

## Cara Menjalankan

Jalankan langsung di Cloud Shell:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp199.sh
bash gsp199.sh
```

Region dan Zone ditanyakan di awal (default `us-east4` dan `us-east4-c`). Cukup tekan `Enter` jika cocok dengan panel lab.

Setelah script menampilkan banner `SELESAI!`, klik kedua tombol **Check my progress** di panel lab:
1. *Create and Manage Service Accounts*
2. *Access BigQuery using a Service Account*

## Detail Teknis

- **Isolasi stdin SSH dan SCP:** Pemanggilan `gcloud compute scp` dan `gcloud compute ssh` dipasangi `< /dev/null` agar tidak memotong pipeline saat script dijalankan melalui `curl ... | bash`.
- **Ekspansi Metadata di VM:** Script remote mengambil `project-id` dan `service-accounts/default/email` langsung dari metadata server instance, sehingga selalu cocok tanpa dependensi path string.
