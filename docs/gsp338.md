# GSP338 - Monitor and Log with Google Cloud Observability: Challenge Lab

Runbook untuk [`gsp338.sh`](../gsp338.sh) dan [`gsp338_fix.sh`](../gsp338_fix.sh).
Status: script utama turunan solusi komunitas yang sudah terbukti (pspcps/Arcade,
ePlus-DEV/storage, knsiuss/gcp); belum dijalankan di instance lab sendiri.
`gsp338_fix.sh` dibuat untuk memperbaiki dua task yang gagal karena script
pihak ketiga (KenilithCloudx.sh) memakai versi lama filter log metric dan
tidak mengurus dashboard.

Arcade: 5 credits, 25 menit, Intermediate. Terkait badge **Observability** /
monitoring ops (cek SKILL_CATALOG tracker untuk kode badge persisnya).

## Kenapa lab ini cocok di-script

Kelima task bisa dikerjakan lewat gcloud API: services enable, update metadata
startup script, `gcloud logging metrics`, `gcloud monitoring dashboards`, dan
alert policy. Satu-satunya bagian yang perlu kesabaran adalah soal waktu —
custom metric baru muncul 5-10 menit setelah log masuk.

## Sebelum jalan

1. Start lab, buka Cloud Shell.
2. VM `video-queue-monitor` sudah di-provision lab saat start (jangan dibuat
   sendiri). Tunggu sampai "Running", script akan menunggu otomatis.
3. Catat nama log metric dan threshold alert dari panel lab. Versi terbaru
   pakai `big_video_upload_rate` threshold 3; versi lama pakai
   `huge_video_upload_rate` threshold 4. Script bertanya di awal (default
   versi terbaru).

## Apa yang diotomasi

| Task | Poin | Status | Catatan |
|------|------|--------|---------|
| Task 1: Enable Cloud Monitoring | auto | ✅ | `gcloud services enable monitoring.googleapis.com` (+ logging, compute, cloudfunctions) |
| Task 2: Custom metric video queue | auto | ✅ | update metadata `startup-script` → install Go 1.22.8 + ops agent, set `MY_PROJECT_ID`/`MY_GCE_INSTANCE_ID`/`MY_GCE_INSTANCE_ZONE`, jalankan Go app dari `gs://spls/gsp338/video_queue/main.go`; restart instance |
| Task 3: Log metric upload rate | auto | ✅ | `gcloud logging metrics create big_video_upload_rate --log-filter='textPayload=~"file_format\: ([4,8]K).*"'` |
| Task 4: 2 chart di Media_Dashboard | auto | ✅ | PATCH dashboard: widget upload rate (`ALIGN_RATE`) + queue length (`ALIGN_MEAN`); handle layout `mosaicLayout` maupun `gridLayout` |
| Task 5: Alert custom | auto | ✅ | `gcloud alpha monitoring policies create` (threshold > N/s, `ALIGN_RATE`, metric `logging.googleapis.com/user/<METRIC>`), fallback REST |

## Yang diketahui mengecoh

- **Filter log metric berubah antar versi lab.** Ini penyebab utama script
  pihak ketiga gagal Task 3. Versi yang benar-cepat: `textPayload=~"file_format\: ([4,8]K).*"` (regex).
  Filter versi lama `textPayload=("file_format=4K" OR "file_format=8K")` **tidak**
  dihitung oleh grader versi baru. `gsp338_fix.sh` meng-update filter ke regex
  bila metric sudah terlanjur dibuat dengan filter lama.
- **KenilithCloudx.sh tidak menyentuh dashboard.** Script populer itu berhenti
  setelah alert policy, makanya Task 4 selalu 0/20 kalau cuma pakai dia.
- Nama metric bisa `big_video_upload_rate` (baru) atau `huge_video_upload_rate`
  (lama) tergantung versi lab. Selalu cocokkan nama persisnya di panel lab,
  script bertanya di awal.
- Threshold alert: 3/s (baru) vs 4/s (lama).
- Dashboard PATCH gagal total jika dashboard belum kelihatan saat monitoring
  API baru di-enable; script menunggu sampai findable (retry 10×20 detik).
