# ARC119 - Create a Secure Data Lake on Cloud Storage: Challenge Lab

Runbook untuk [`arc119.sh`](../arc119.sh). Status: **terverifikasi 100/100** (2026-08-22). Versi pertama script gagal di Task 4 karena memakai API Data Catalog; sudah diperbaiki, lihat temuan utama di bawah.

## Cara jalan

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/arc119.sh | bash
```

Satu pertanyaan: region (default `us-west1`).

| Task | Otomatis | Cara |
|------|----------|------|
| 1 Bucket + asset | ya | `gcloud storage buckets create gs://<project>-bucket` + `dataplex assets create --resource-type=STORAGE_BUCKET` |
| 2 Lake + zone | ya | `dataplex lakes create customer-lake` + `dataplex zones create public-zone --type=RAW --resource-location-type=SINGLE_REGION --discovery-enabled --labels=domain_type=source_data` |
| 3 Entry group | ya | `dataplex entry-groups create custom-entry-group --display-name="Custom entry group"` |
| 4 "Tag template" | ya | **`dataplex aspect-types create`**, bukan `data-catalog tag-templates` |

## Temuan utama: "tag template" = aspect type, API Data Catalog sudah mati

Instruksi lab masih memakai istilah lama ("tag template", "Data Catalog entry", "source system CLOUD STORAGE"), tapi di project lab API-nya sudah dimatikan:

```
ERROR: (gcloud.data-catalog.tag-templates.describe) INVALID_ARGUMENT:
Project qwiklabs-... is not allowed to perform read operations
due to Data Catalog deprecation.
WARNING: This command is deprecated. Please use `gcloud dataplex aspect-types` instead.
```

Jadi yang dinilai adalah **aspect type Knowledge Catalog** dengan display name `Customer Data Tag Template` dan ID `customer-data-tag-template`. Field-nya dipetakan begini:

| Kolom tabel lab | Di aspect type |
|-----------------|----------------|
| Data Owner, Text | `data_owner`, `type: string`, `annotations.displayName: Data Owner` |
| PII Data, Enum Yes/No | `pii_data`, `type: enum`, `enumValues` Yes dan No |

Konsekuensi lain: **tidak perlu menempel tag ke entry bucket sama sekali**. Task 4 langsung 25/25 begitu aspect type-nya dibuat — terbukti 2026-08-22. Instruksi soal menyuruh mencari entry di bawah source system `CLOUD STORAGE` lalu menempelkan tag, tapi grader tidak memeriksanya. Versi pertama script membuang waktu mencari entry itu di Knowledge Catalog search (hasilnya kosong, "No rows to display") dan lewat `data-catalog search` (ditolak deprecation).

Ini kembaran temuan ARC117 dan GSP514: **penempelan aspect/tag ke entry hampir tidak pernah jadi syarat checkpoint**, dan entry Dataplex sering tidak pernah muncul. Jangan menunggunya.

## Urutan dibalik dari nomor task

Task 1 menyuruh "attach as an asset to the zone", tapi zone-nya baru dibuat di Task 2. Script membuat **lake dan zone dulu**, baru bucket dan asset. Checkpoint tidak peduli urutan eksekusi.

## Lab ini memakai dua user

Instruksi menyuruh Task 1 dikerjakan sebagai **User 1** dan Task 2 sebagai **User 2**. Pada percobaan yang berhasil, **semuanya dikerjakan dari satu Cloud Shell** dan keempat checkpoint hijau — pembagian user itu ternyata tidak diperiksa grader.

Script tetap tidak berhenti di task yang gagal: yang gagal dicatat, dicetak di akhir, dan script keluar dengan status bukan-nol. Kalau suatu saat memang kena `PERMISSION_DENIED`:

```bash
gcloud auth login
bash arc119.sh     # aman diulang, yang sudah ada dilewat
```

## ID diturunkan dari display name

Instruksi menulis ID "Leave the default value", artinya console menurunkannya dari display name: `Customer-Lake` → `customer-lake`, `Public-Zone` → `public-zone`, `Custom entry group` → `custom-entry-group`. Nama berspasi tidak valid sebagai ID. Kalau checkpoint merah, cek ID sebenarnya di console lalu ulangi dengan `LAKE_ID=... ZONE_ID=... EG_ID=... bash arc119.sh`.

Catatan: project lab sudah berisi lake bawaan bernama `public-lake`. Abaikan, tidak bertabrakan dengan `customer-lake` yang dibuat script.

## Task lab berganti tiap kali lab dimulai

Halaman lab menyatakan sendiri: "For each time when you start the lab, you get different tasks". Script ini mengikuti varian Customer-Lake / Public-Zone / Custom entry group / Customer Data Tag Template. Kalau nama-namanya berbeda:

```bash
LAKE_ID=... ZONE_ID=... EG_ID=... TT_ID=... BUCKET=... bash arc119.sh
```

Display name masih di-hardcode; kalau yang berubah display name-nya, edit langsung di script.

## Idempoten

Aman diulang. Semua create didahului `describe`.

## Kalau gagal

- **`... due to Data Catalog deprecation`** — masih ada perintah `gcloud data-catalog` yang tersisa. Semua sudah diganti `gcloud dataplex`; kalau muncul lagi berarti script yang dipakai versi lama, ambil ulang lewat commit SHA (lihat [README](../README.md)).
- **Lake stuck di `CREATING`** — normal, bisa 3 menit.
- **Zone ditolak karena label** — format flagnya `--labels=domain_type=source_data`, satu tanda sama dengan, tanpa kutip.
- **Aspect type ditolak** — cek `python3 -m json.tool` atas template-nya; `enumValues` wajib punya `index` dan `name`.
