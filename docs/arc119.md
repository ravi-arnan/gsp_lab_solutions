# ARC119 - Create a Secure Data Lake on Cloud Storage: Challenge Lab

Runbook untuk [`arc119.sh`](../arc119.sh). Status: **belum diuji di lab sungguhan** — baru `bash -n`.

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/arc119.sh
bash arc119.sh
```

Dua pertanyaan: region (default `us-west1`) dan nama untuk field **Data Owner** di tag Task 4.

| Task | Otomatis | Cara |
|------|----------|------|
| 1 Bucket + asset | ya | `gcloud storage buckets create gs://<project>-bucket` + `dataplex assets create --resource-type=STORAGE_BUCKET` |
| 2 Lake + zone | ya | `dataplex lakes create customer-lake` + `dataplex zones create public-zone --type=RAW --resource-location-type=SINGLE_REGION --discovery-enabled --labels=domain_type=source_data` |
| 3 Entry group | ya | dibuat di **dua** API sekaligus, lihat di bawah |
| 4 Tag template | ya | `data-catalog tag-templates create` dengan field `string` + `enum(Yes\|No)` |
| 4 Tempel tag ke entry | mungkin | butuh entry Cloud Storage sudah ada di Data Catalog; kalau belum, instruksi UI dicetak |

## Urutan dibalik dari nomor task

Task 1 menyuruh "attach as an asset to the zone", tapi zone-nya baru dibuat di Task 2. Script membuat **lake dan zone dulu**, baru bucket dan asset. Checkpoint tidak peduli urutan eksekusi.

## Lab ini memakai dua user

Instruksi menyuruh Task 1 dikerjakan sebagai **User 1** dan Task 2 sebagai **User 2**, dan kedua akun itu punya IAM berbeda. Script tidak bisa berganti akun sendiri, jadi:

- Kegagalan satu task **tidak menghentikan** script. Yang gagal dicatat dan dicetak di akhir, lalu script keluar dengan status bukan-nol.
- Kalau errornya `PERMISSION_DENIED`, login sebagai user yang diminta dan jalankan ulang:

  ```bash
  gcloud auth login
  bash arc119.sh
  ```

  Semua langkah dilewat kalau resource-nya sudah ada, jadi mengulang aman dan cepat.

Ini menyalahi aturan "jangan telan error" di [AGENTS.md](../AGENTS.md) secara bentuk, bukan secara maksud: errornya **dicetak utuh** dan diringkas lagi di akhir, yang dihindari cuma berhenti di task 1 padahal task 3 dan 4 masih bisa jalan dengan akun yang sama.

## Entry group dibuat di dua API

"Entry groups" di console sekarang milik Knowledge Catalog (Dataplex), tapi tag template di Task 4 masih memakai API **Data Catalog** yang lama. Mana yang dibaca grader belum terbukti, jadi script membuat keduanya:

- `gcloud dataplex entry-groups create custom-entry-group --display-name="Custom entry group"`
- `gcloud data-catalog entry-groups create custom_entry_group --display-name="Custom entry group"`

Masing-masing satu perintah, dan yang gagal tidak menjatuhkan yang lain; Task 3 baru dianggap gagal kalau dua-duanya gagal. Perhatikan bedanya ID: Dataplex hanya menerima tanda hubung, Data Catalog hanya menerima garis bawah.

Instruksi lab menulis "Entry Group Name: Custom entry group" — itu **display name**, bukan ID; nama dengan spasi tidak valid sebagai ID di kedua API.

## ID lake dan zone diturunkan dari display name

Instruksi menulis ID "Leave the default value", artinya console menurunkannya dari display name: `Customer-Lake` → `customer-lake`, `Public-Zone` → `public-zone`. Itu yang dipakai script. Kalau checkpoint tetap merah, cek ID sebenarnya di console lalu ulangi dengan `LAKE_ID=... ZONE_ID=... bash arc119.sh`.

## Penempelan tag mungkin harus lewat UI

Entry Cloud Storage untuk bucket baru muncul di Data Catalog **setelah discovery zone Dataplex jalan**, dan itu bisa 5-15 menit. Script mencoba dua jalur (`entries lookup` dengan linked resource, lalu `data-catalog search`), dan kalau tidak ketemu langsung mencetak langkah UI — tidak menunggu.

Alasannya pengalaman GSP514 dan ARC117: menunggu entry Dataplex muncul tidak pernah menolong, dan menghabiskan waktu lab. Kalau tag belum menempel, tunggu beberapa menit lalu **jalankan ulang script**; semua yang sudah ada dilewat dan hanya bagian tag yang dicoba lagi.

## Task lab berganti tiap kali lab dimulai

Halaman lab menyatakan sendiri: "For each time when you start the lab, you get different tasks". Script ini mengikuti varian dengan Customer-Lake / Public-Zone / Custom entry group / Customer Data Tag Template. Kalau nama-namanya berbeda, timpa lewat env var:

```bash
LAKE_ID=... ZONE_ID=... EG_ID=... DC_EG_ID=... TT_ID=... BUCKET=... bash arc119.sh
```

Display name masih di-hardcode; kalau yang berubah display name-nya, edit langsung di script.

## Idempoten

Aman diulang. Semua create didahului `describe`, dan `data-catalog tags create` dilewat kalau tag templatenya sudah ada tapi entry-nya belum ketemu.

## Kalau gagal

- **`PERMISSION_DENIED`** — lihat bagian dua user di atas.
- **Lake stuck di `CREATING`** — normal, bisa 3 menit. `gcloud dataplex lakes describe customer-lake --location=us-west1`.
- **Zone ditolak karena label** — format flagnya `--labels=domain_type=source_data`, satu tanda sama dengan, tanpa kutip.
- **Tag template ditolak di field enum** — sintaksnya `type='enum(Yes|No)'`, tanda kutip wajib supaya `|` tidak jadi pipe shell.
