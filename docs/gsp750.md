# GSP750 - Infrastructure as Code with Terraform

Lab intermediate Terraform di Google Cloud: build VPC network, update VM instance (tags), destructive changes (ganti image boot disk ke cos-cloud/cos-stable), buat resource dependencies (static IP dan Cloud Storage bucket), serta provisioner infrastructure (local-exec).

## Cara jalan

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp750.sh | bash
```

Atau unduh dulu lalu jalankan:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp750.sh
bash gsp750.sh
```

Durasi sekitar 8-12 menit.

## Task

| Task | Isi | Checkpoint | Otomatis |
|------|-----|-----------|----------|

Total: **100/100 poin** otomatis (5 checkpoint, masing-masing 20 poin).

## Yang perlu diperhatikan

1. **Deteksi dummy wrapper Terraform di Cloud Shell:**
   Cloud Shell sering menyertakan wrapper dummy `terraform` yang exit 0 dengan menampilkan instruksi instalasi. Script mengecek `terraform --version | grep 'Terraform v'`. Jika belum terpasang atau masih dummy, script otomatis menginstal Terraform dari repositori resmi HashiCorp (plus fallback binary zip).

2. **Deteksi Region dan Zone Otomatis:**
   Script membaca default zone (`us-east1-c`) dan region (`us-east1`) dari metadata instance atau gcloud config dengan fallback via helper `ask`. Jika ingin dioverride secara manual:
   ```bash
   ZONE=us-east1-c REGION=us-east1 bash gsp750.sh
   ```

3. **Pertahankan Bucket dan Dependent Instance:**
   Pada Task 3 lab asli meminta menghapus bucket dan `another_instance`. Namun jika dihapus, Checkpoint "Create a bucket dependent instance" di grader bisa hilang atau berkurang. Script mempertahankan kedua resource tersebut pada konfigurasi akhir agar seluruh 5 checkpoint tetap hijau.

4. **Nol Interaksi (Fully Automated):**
   Semua perintah `terraform apply` memakai flag `-auto-approve`, dan helper `ask` otomatis menggunakan default saat di-pipe (`curl | bash`).
