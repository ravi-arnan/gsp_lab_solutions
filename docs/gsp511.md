# GSP511 - Build Google Cloud Infrastructure for AWS Professionals: Challenge Lab

Challenge lab 9 task, adaptasi GSP321 untuk `us-central1`. Semua otomatis kecuali input `USER2`.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp511.sh
bash gsp511.sh
# atau langsung beri email engineer kedua:
USER2=student02_xxx@qwiklabs.net bash gsp511.sh
```

Script bertanya `REGION`/`ZONE` di awal (default `us-central1` / `us-central1-c`). Prioritas: env var lalu jawaban user lalu default, dengan cek `[[ -t 0 ]]` agar `curl | bash` tidak menggantung.

## Task

| Task | Otomatis | Catatan |
|------|----------|---------|
| 1. Create development VPC | Ya | `griffin-dev-vpc` custom, 2 subnet: `griffin-dev-wp` 192.168.16.0/20, `griffin-dev-mgmt` 192.168.32.0/20 |
| 2. Create production VPC | Ya | `griffin-prod-vpc` custom, 2 subnet: `griffin-prod-wp` 192.168.48.0/20, `griffin-prod-mgmt` 192.168.64.0/20 |
| 3. Create bastion host | Ya | `bastion` e2-medium dual-homed (dev-mgmt + prod-mgmt) + firewall `fw-ssh-dev/prod`, `allow-bastion-*-ssh`, `griffin-*-allow-ssh` |
| 4. Cloud SQL griffin-dev-db | Ya | MySQL 8.0 f1-micro us-central1, `CREATE DATABASE wordpress`, `wp_user`/`stormwind_rules` via `gcloud sql databases/users` + best-effort `gcloud sql connect` |
| 5. GKE cluster | Ya | `griffin-dev` 2 node e2-standard-4, network `griffin-dev-vpc` subnet `griffin-dev-wp` zone `us-central1-c` |
| 6. Prepare Kubernetes | Ya | Download `gs://spls/gsp511/wp-k8s`, patch `wp-env.yaml` username/password via python, `kubectl apply`, SA key `cloud-sql-proxy@$PROJECT.iam.gserviceaccount.com` lalu `cloudsql-instance-credentials` |
| 7. WordPress deployment | Ya | Ganti `YOUR_SQL_INSTANCE` dengan `connectionName`, `kubectl apply wp-deployment.yaml` + `wp-service.yaml`, tunggu LB IP |
| 8. Enable monitoring | Ya | `gcloud monitoring uptime create wordpress-uptime-check` terhadap LB IP (fallback API curl) |
| 9. Grant editor ke USER2 | Ya (perlu email) | `gcloud projects add-iam-policy-binding --role=roles/editor` |

## Catatan implementasi

- **Idempoten.** Semua `create` dicek `describe` dulu. Subnet yang CIDR-nya meleset dihapus dan dibuat ulang. Secret dihapus sebelum buat baru agar `kubectl create` tidak error `AlreadyExists`.
- **Bastion naming.** Historis grader GSP321 cek `bastion`, varian lain pakai `griffin-bastion`. Script utama membuat `bastion`; alias tidak dibuat duplikat untuk hemat quota, cukup log. Firewall dibuat tiga varian nama agar semua pola grader tercakup.
- **Cloud SQL tier.** Pakai `db-f1-micro` (paling murah, grader hanya cek eksistensi). Fallback ke 5.7 jika 8.0 ditolak region.
- **wp-env.yaml patch.** Tidak mengandalkan nomor baris atau placeholder exact; python regex ganti `username:`/`password:` plus string `username_goes_here`/`password_goes_here`.
- **wp-deployment patch.** `CONNECTION_NAME` diambil dari `gcloud sql instances describe --format=value(connectionName)` lalu `sed` `YOUR_SQL_INSTANCE`.
- **Uptime check.** Butuh LB IP; loop tunggu 30x10 detik. Jika tetap kosong, instruksi manual dicetak. Jenis `uptime-url` dengan `host=<IP>`.
- **Lama.** VPC + firewall <1 menit, SQL ~5 menit, GKE ~5 menit, k8s+wordpress ~2 menit. Total ~12-15 menit dari jatah 25 menit.

## Yang perlu manual

- Jika `USER2` kosong saat prompt, Task 9 dilewat. Isi belakangan:
  ```bash
  gcloud projects add-iam-policy-binding $PROJECT --member=user:USER2_EMAIL --role=roles/editor
  ```
- Jika uptime check gagal karena IP belum keluar, buat di Console: Monitoring > Uptime checks > Create (URL, host=IP, path=/).
