# GSP413 — Creating a Data Warehouse Through Joins and Unions

Lab terakhir yang kurang untuk badge **624 Build a Data Warehouse with BigQuery**.

## Cara jalan

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp413.sh | bash
```

Tidak ada parameter per-instance. Semua nama dataset dan tabel tetap.

## Task

| Task | Isi | Checkpoint | Otomatis |
|------|-----|-----------|----------|
| 1 | Create a new dataset to store your tables | ya | ya |
| 2 | Explore the product sentiment dataset | ya | ya |
| 3 | Join datasets to find insights | ya | ya |
| 4 | Append additional records | ya | ya |

Keempatnya di-score dan keempatnya diotomasi. Soal pilihan ganda tetap manual.

## Jebakan yang paling sering bikin Task 2 merah

Task 2 kelihatan seperti task "baca-baca saja" — dua query `SELECT` untuk melihat
sentimen produk. Tapi langkah pertamanya membuat salinan tabel:

```sql
CREATE OR REPLACE TABLE ecommerce.products AS
SELECT * FROM `data-to-insights.ecommerce.products`
```

Itu satu-satunya perubahan state di Task 2, jadi itulah yang dicari checkpoint.
Banyak script komunitas melewatkannya karena kelihatan tidak penting, dan Task 2-nya
tidak pernah hijau. Script ini menyertakannya.

## Nama tabel yang dicari checkpoint

- `ecommerce.products` — Task 2
- `ecommerce.sales_by_sku_20170801` — Task 3, harus berisi 462 SKU
- `ecommerce.sales_by_sku_20170802` — Task 4, satu baris hasil `INSERT`

## Location

Dikunci ke **US**. `data-to-insights` ada di US multi-region dan BigQuery menolak
join lintas-location. Script memakai `bq --location=US mk`, tidak mengandalkan
default akun — kalau default-mu bukan US, script komunitas yang cuma `bq mk ecommerce`
akan bikin dataset di tempat salah dan semua join gagal.

Query wildcard ditulis fully-qualified (`` `PROJECT.ecommerce.sales_by_sku_2017*` ``).
Bentuk pendek `ecommerce.sales_by_sku_2017*` hanya resolve kalau ada default dataset,
dan `bq query` tidak punya itu.
