# GSP1157 - Implementing Security in Knowledge Catalog

Runbook untuk [`gsp1157.sh`](../gsp1157.sh). Status: terverifikasi di us-west1, upload User 2 berhasil (2026-07-17).

## Peringatan utama

**Lab ini pakai dua user.** Cloud Shell login sebagai User 1 saja. Task 3 dan 5 harus dikerjakan sebagai User 2 lewat console UI, dan itu **tidak bisa diotomasi dari sini**. Script mengerjakan Task 1, 2, dan 4.

**Script dua fase.** Fase `writer` sengaja **tidak** mencabut role Reader, jadi urutan klik checkpoint tidak bisa merusak skor. Pemisahan fase tetap ada karena Task 3 (upload harus ditolak) hanya masuk akal saat User 2 masih Reader saja.

**Region diisi dinamis per instance.** Default script `us-central1`, cocokkan dengan halaman lab.

## Sebelum jalan

1. Start lab, login sebagai **User 1**, buka Cloud Shell.
2. Catat **Region** dari tabel properti Task 1.
3. Catat **email User 2** dari panel Lab setup and access. Jangan asumsikan `student-02`: nomornya tidak berurutan, pernah ketemu `student-01` sebagai User 1 dan `student-03` sebagai User 2.
4. Bucket `<sesuatu>-bucket` disiapkan lab. Script mendeteksinya sendiri, tidak perlu diisi.

**Fase 3** (opsional, Task 3, tanpa checkpoint): logout, login UI sebagai User 2, buka bucket, coba Upload. **Harus ditolak.** Itu inti pelajarannya, jadi sayang kalau dilewat.

Klik Check my progress untuk *Assign Knowledge Catalog Data Writer role*.

**Fase 5** (Task 5), sebagai User 2 lewat UI:

1. Logout, login sebagai User 2.
2. Navigation menu > Cloud Storage > Buckets.
3. Klik bucket `<sesuatu>-bucket`.
4. Upload > Upload files, pilih file apa saja.
5. Kali ini harus berhasil. Klik Check my progress terakhir.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `tidak ada bucket berakhiran '-bucket'` | Provisioning lab belum selesai. Tunggu, refresh halaman lab, jalankan ulang. Script mencetak daftar bucket yang ada untuk membantu. |
| `USER2 belum diisi` | Ambil email User 2 dari panel Lab setup, bukan User 1. |
| Checkpoint Data Reader 0/25 (versi script lama) | Versi awal mencabut reader saat fase `writer`. Sudah diperbaiki. Kalau masih kena, jalankan `reader` lagi untuk memasang binding reader kembali, lalu klik checkpoint. Poin yang sudah hijau tidak hilang. |
| Upload User 2 masih ditolak di Task 5 | Permission butuh beberapa menit menyebar. Tunggu, refresh, coba lagi. |
| Upload User 2 berhasil padahal di Task 3 | Kamu sudah menjalankan fase `writer`. Task 3 harus dicoba saat role masih Reader. |
| `NOT_FOUND` di fase `writer` | Region salah, atau fase `reader` belum pernah jalan. |

## Catatan

Fase `writer` menyimpang sedikit dari lab: console "Edit principal" mengganti role, sedangkan script menambah Writer tanpa mencabut Reader. Checkpoint hanya memeriksa keberadaan binding Writer dan tidak menuntut Reader hilang, jadi menyimpan keduanya membuat kedua checkpoint aman di urutan apa pun. Versi pertama meniru console persis dan justru menghasilkan Data Reader 0/25 saat fase `writer` dijalankan sebelum checkpoint-nya diklik.

Task 5 sengaja tidak diotomasi. Secara teknis User 1 bisa saja meng-upload file ke bucket itu dan checkpoint mungkin lolos, tapi itu melewatkan seluruh inti labnya: membuktikan bahwa role yang berbeda menghasilkan hasil yang berbeda untuk user yang sama. Upload-nya cuma tiga klik sebagai User 2.
