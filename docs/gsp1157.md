# GSP1157 - Implementing Security in Knowledge Catalog

Runbook untuk [`gsp1157.sh`](../gsp1157.sh). Status: **belum diuji**.

## Peringatan utama

**Lab ini pakai dua user.** Cloud Shell login sebagai User 1 saja. Task 3 dan 5 harus dikerjakan sebagai User 2 lewat console UI, dan itu **tidak bisa diotomasi dari sini**. Script mengerjakan Task 1, 2, dan 4.

**Script dua fase.** Task 4 mengganti role User 2 dari Reader jadi Writer, persis seperti tombol "Edit principal" di console. Kalau fase `writer` dijalankan sebelum checkpoint Data Reader diklik, checkpoint itu gagal karena binding-nya sudah tidak ada.

**Region diisi dinamis per instance.** Default script `us-central1`, cocokkan dengan halaman lab.

## Pembagian kerja

| Task | Siapa | Cara | Checkpoint |
|------|-------|------|------------|
| 1. Lake, zone, asset | User 1 | script, fase `reader` | Ya |
| 2. Grant Data Reader | User 1 | script, fase `reader` | Ya |
| 3. Upload ditolak | User 2 | UI, manual | Tidak ada |
| 4. Grant Data Writer | User 1 | script, fase `writer` | Ya |
| 5. Upload berhasil | User 2 | UI, manual | Ya |

## Sebelum jalan

1. Start lab, login sebagai **User 1**, buka Cloud Shell.
2. Catat **Region** dari tabel properti Task 1.
3. Catat **email User 2** dari panel Lab setup and access.
4. Bucket `<sesuatu>-bucket` disiapkan lab. Script mendeteksinya sendiri, tidak perlu diisi.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `tidak ada bucket berakhiran '-bucket'` | Provisioning lab belum selesai. Tunggu, refresh halaman lab, jalankan ulang. Script mencetak daftar bucket yang ada untuk membantu. |
| `USER2 belum diisi` | Ambil email User 2 dari panel Lab setup, bukan User 1. |
| Checkpoint Data Reader merah setelah fase `writer` | Kamu menjalankan `writer` terlalu cepat. Binding reader sudah dicabut. Jalankan `reader` lagi untuk memasangnya kembali, klik checkpoint, baru `writer`. |
| Upload User 2 masih ditolak di Task 5 | Permission butuh beberapa menit menyebar. Tunggu, refresh, coba lagi. |
| Upload User 2 berhasil padahal di Task 3 | Kamu sudah menjalankan fase `writer`. Task 3 harus dicoba saat role masih Reader. |
| `NOT_FOUND` di fase `writer` | Region salah, atau fase `reader` belum pernah jalan. |

## Catatan

Task 5 sengaja tidak diotomasi. Secara teknis User 1 bisa saja meng-upload file ke bucket itu dan checkpoint mungkin lolos, tapi itu melewatkan seluruh inti labnya: membuktikan bahwa role yang berbeda menghasilkan hasil yang berbeda untuk user yang sama. Upload-nya cuma tiga klik sebagai User 2.
