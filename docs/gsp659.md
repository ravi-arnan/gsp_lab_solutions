# GSP659 - Deploy Your Website on Cloud Run

Runbook untuk [`gsp659.sh`](../gsp659.sh). Status: terverifikasi 100/100 (2026-08-21, us-west1).

## Sebelum jalan

1. Start lab, login pakai kredensial student.
2. Buka Cloud Shell.
3. Cek region di panel lab. Default script `us-west1`, sesuai instruksi lab.
   Region dipakai untuk repository Artifact Registry sekaligus service Cloud Run,
   jadi kalau lab-mu beda, isi lewat `REGION=...` atau jawab saat ditanya.

## Jalankan

Dua fase, jadi **download dulu**, jangan `curl | bash` — filenya masih dibutuhkan
untuk fase kedua, dan `curl ... | bash -s update` membuat script berebut stdin.

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp659.sh
bash gsp659.sh                 # Task 1-4, sekitar 6-8 menit
# klik Check my progress 1, 2, 3 sampai hijau
bash gsp659.sh update          # Task 4b-6, sekitar 4 menit
```

## Kenapa dua fase

Lab menyuruh mengembalikan concurrency ke 80 persis setelah checkpoint 3, di
paragraf yang sama. Kalau grader memeriksa revisi yang sedang aktif dan bukan
sekadar riwayat revisi, mengembalikannya sebelum checkpoint diklik bisa membuat
poinnya hilang. Fase `update` memisahkan itu; urutannya tetap sama dengan lab.

## Penyimpangan dari teks lab

- **`./setup.sh` tidak dijalankan.** Script itu meng-install dependency monolith,
  microservices, dan react-app lalu build React untuk semuanya. Yang benar-benar
  dibutuhkan cuma react-app: `monolith/public` (yang di-`COPY` Dockerfile) adalah
  hasil `npm run build:monolith`, sedangkan dependency monolith di-install di
  dalam container oleh `RUN npm install`. Melewati sisanya menghemat beberapa
  menit sekaligus menjaga `node_modules` tidak ikut terkirim ke Cloud Build.
- **Preview `npm start` di Task 1 dilewat** — memblokir terminal, tidak dinilai.
  Websitenya tetap bisa dibuka dari URL Cloud Run yang dicetak di akhir fase 1.
- **`--platform managed` ditambahkan di tiap `gcloud run deploy`.** Kalau
  `run/platform` belum di-set, gcloud akan bertanya target platform dan
  menggantung di eksekusi non-interaktif.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `Repository ... already exists` | Repo Artifact Registry sudah dibuat manual lewat console. Aman, script melewatinya sendiri. |
| Build gagal `denied: Permission ... artifactregistry.repositories.uploadArtifacts` | Repo dibuat di region lain. Cocokkan `REGION` dengan repo yang ada. |
| `npm run build:monolith` gagal | Clone rusak atau setengah jalan. `rm -rf ~/monolith-to-microservices` lalu jalankan ulang fase 1, script idempoten. |
| Fase update bilang `~/monolith-to-microservices tidak ada` | Fase 1 belum pernah jalan, atau home Cloud Shell di-reset. Jalankan `bash gsp659.sh` dulu. |
| Homepage masih judul lama setelah fase 2 | Revisi baru butuh beberapa detik menerima trafik. Hard refresh (Ctrl+Shift+R). |
