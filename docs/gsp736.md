# GSP736 - Debug Apps on Google Kubernetes Engine

Tiga checkpoint, semuanya otomatis. Cluster `central` sudah disiapkan lab.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp736.sh
bash gsp736.sh
```

Akan ditanya zone dan nama cluster (default `us-central1-a` / `central`).

## Task

| Task | Otomatis | Catatan |
|------|----------|---------|
| 1. Infrastructure setup | Ya | tunggu cluster RUNNING, `get-credentials` |
| 2. Deploy an application | Ya | clone repo, `kubectl apply`, tunggu deployment + External IP |
| 4. Create a logs-based metric | Ya | `Error_Rate_SLI` |
| 5. Create an alerting policy | Ya | `Error Rate SLI`, ALIGN_RATE, threshold 0.5 |
| 3, 6. Buka app, perbaiki bug | Ya (tanpa checkpoint) | hapus `ENABLE_RELOAD` lalu apply ulang |

## Grader mencocokkan teks filter alerting policy

Diuji 2026-08-04. Policy pertama ditolak (`Please create a alerting policy named
'Error Rate SLI' with specific configurations`) padahal semua nilainya benar:
displayName, metric `logging/user/Error_Rate_SLI`, `thresholdValue` 0.5,
`perSeriesAligner` ALIGN_RATE, tanpa notification channel.

Yang berbeda cuma **penulisan filternya**. Ditolak:

```
metric.type="logging.googleapis.com/user/Error_Rate_SLI" AND resource.type="k8s_container"
```

Diterima — urutan seperti keluaran UI, `resource.type` dulu dan ada spasi di
sekitar `=`:

```
resource.type = "k8s_container" AND metric.type = "logging.googleapis.com/user/Error_Rate_SLI"
```

Jadi grader lab ini membandingkan string, bukan menguraikan filternya. Perlu
dicatat bahwa ini **tidak berlaku umum**: alerting policy di
[gsp089](gsp089.md), [gsp1108](gsp1108.md), dan [arc115](arc115.md) lolos dengan
urutan `metric.type` dulu. Kalau checkpoint alert menolak padahal nilainya
sudah benar, coba ubah urutan filternya sebelum mencari penyebab lain.

Sekalian ditambahkan `alertStrategy.autoClose` dan `notificationChannels: []`
supaya bentuknya sama persis dengan hasil UI.

## Catatan lain

- **Nomor baris `ENABLE_RELOAD` dicari sendiri**, tidak di-hardcode `373,374`
  seperti instruksi lab — manifest di repo hulu bisa bergeser.
- Filter logs-based metric ditulis persis seperti lab, termasuk operator `:`
  pada `labels."k8s-pod/app"`, dengan alasan yang sama.
- Task 6 tetap dikerjakan walau tanpa checkpoint supaya
  `productcatalogservice` berhenti crash. Kalau ingin melihat error-nya dulu
  seperti alur belajar lab, buka Locust dan swarm 300 user sebelum tahap itu.
