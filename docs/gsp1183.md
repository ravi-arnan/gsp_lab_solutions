# GSP1183 - Gating Deployments with Binary Authorization

Runbook untuk [`gsp1183.sh`](../gsp1183.sh). Status: terverifikasi di us-east1 / us-east1-c, ketujuh checkpoint hijau sekali jalan (2026-07-17).

## Kenapa lab ini enak di-script

Seluruh langkahnya sudah berupa perintah CLI, tidak ada satu pun aksi klik UI yang di-score. Ketujuh checkpoint bisa diotomasi penuh. Ini kebalikan dari GSP1145 atau GSP1157.

## Peringatan utama

**Butuh REGION dan ZONE, dan keduanya berbeda.** Cluster GKE dibuat zonal (`--zone`), sedangkan Artifact Registry pakai region. Cocokkan dengan halaman lab.

**Lama: sekitar 15-20 menit dari jatah 35 menit.** Cluster GKE sendiri ~5 menit, Cloud Build tiga kali, plus dua kali tunggu propagasi policy. Jalankan sedini mungkin.

**Task 5d dan Task 8 memang harus GAGAL.** Itu inti labnya: membuktikan Binary Authorization memblokir. Script memperlakukan kegagalan di dua titik itu sebagai sukses, dan `set -e` tidak akan membunuhnya.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp1183.sh
REGION=<region> ZONE=<zone> bash gsp1183.sh
```

Satu fase, idempoten. Aman diulang kalau gagal di tengah: repo, note, attestor, key, cluster, dan image custom step semuanya dicek dulu.

## Bug di teks lab: `COMPUTE_ZONE="REGION"`

Di Task 7 lab menulis:

```
COMPUTE_ZONE="REGION"
...
clusterAdmissionRules:
  ${COMPUTE_ZONE}.binauthz:
```

Kunci `clusterAdmissionRules` formatnya `<lokasi-cluster>.<nama-cluster>`. Cluster ini dibuat **zonal** (`--zone`), jadi kuncinya harus memakai **zone**, bukan region. Script memakai `$ZONE.$CLUSTER`.

Kalau kuncinya salah, tidak ada error. Aturan cluster-nya cuma **diam-diam tidak terpakai**, dan hasil Task 7 serta 8 tetap terlihat benar karena `defaultAdmissionRule` sudah `REQUIRE_ATTESTATION`. Ini jenis bug yang lolos tanpa jejak.

## Beda dari teks lab

| Lab | Script | Alasan |
|-----|--------|--------|
| `edit policy.yaml` | `sed -i` | `edit` itu editor interaktif Cloud Shell, tidak bisa di-script. |
| `COMPUTE_ZONE="REGION"` | `$ZONE` | Lihat bagian di atas. |
| Langsung deploy setelah import policy | `sleep 20` dulu | Policy butuh waktu menyebar, sama seperti IAM. |
| `mkdir vuln-scan && cd` | `mkdir -p $HOME/vuln-scan` | Supaya bisa dijalankan ulang tanpa error. |

## Checkpoint

1. Create Artifact Registry repository
2. Create an Attestor
3. Add a KMS key
4. Create a GKE cluster and update the policies
5. Add a signing step
6. Deploy a signed image
7. Deploy an unsigned image

Task 4 (sign attestation) tidak punya checkpoint, tapi tetap dikerjakan karena Task 7 bergantung padanya.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Deploy di Task 5d malah berhasil | Policy `ALWAYS_DENY` belum menyebar. Script memperingatkan, bukan menganggap sukses. Jalankan ulang bagian itu. |
| Pod Task 7 tidak jalan | Attestation tidak cocok. Cek `gcloud container binauthz attestations list --attestor=vulnz-attestor`. |
| Pod Task 8 malah jalan | Justru masalah: berarti policy tidak menegakkan attestation. Cek `gcloud container binauthz policy export`. |
| `denied by attestor` di Task 8 | **Diharapkan.** Itu hasil yang benar. |
| Cloud Build gagal di `create-attestation` | Role Cloud Build SA belum menyebar. Tunggu, jalankan ulang. |
| Quota / cluster gagal dibuat | Zone salah atau kehabisan resource. Cocokkan zone dengan halaman lab. |
