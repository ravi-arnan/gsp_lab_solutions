# GSP903 - Stream Processing with Cloud Pub/Sub and Dataflow: Qwik Start

Runbook untuk [`gsp903.sh`](../gsp903.sh). Status: terverifikasi 100/100 (2026-08-21, us-central1).

## Sebelum jalan

1. Start lab, login pakai kredensial student, buka Cloud Shell.
2. Cek region di teks lab. Default script `us-central1`; zone dan region App
   Engine diturunkan otomatis darinya.
3. Sediakan 8-12 menit.

## Jalankan

Ada fase `cleanup`, jadi download dulu.

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp903.sh
bash gsp903.sh
```

| Langkah | Aksi | Checkpoint |
|---------|------|------------|

## Tiga keputusan yang berbeda dari teks lab

- **Pipeline dilepas ke latar belakang.** Ini pipeline *streaming*: perintahnya
  tidak pernah selesai sendiri, dan di lab kamu diminta Ctrl+C. Script memakai
  `nohup`, lalu menunggu sampai ada job aktif di `gcloud dataflow jobs list`
  (maksimal 10 menit) sebelum kembali ke prompt. Log di `~/gsp903/pipeline.log`.
  Kalau proses lokalnya mati sebelum job naik, script mencetak 40 baris terakhir
  log itu dan berhenti — bukan menunggu sia-sia sampai batas waktu.
- **Repo tidak di-clone.** Lab menyuruh clone seluruh `python-docs-samples` (atau
  `java-docs-samples`); yang dipakai hanya satu file, jadi diambil langsung.
- **Jalur Python, bukan Java.** `mvn compile exec:java` menarik dependency Maven
  yang jauh lebih berat daripada satu `pip install apache-beam`.

## Klik manual

Empat checkpoint. File output baru muncul beberapa menit setelah job berjalan
karena window-nya 2 menit — tidak ada checkpoint yang menunggunya:

```bash
gcloud storage ls gs://<PROJECT_ID>-bucket/samples/
```

## Bersih-bersih

Pipeline tetap berjalan setelah script selesai. Setelah semua checkpoint hijau:

```bash
bash gsp903.sh cleanup
```

Fase itu menghapus scheduler job, membatalkan job Dataflow yang masih aktif,
lalu menghapus topic dan bucket.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `RESOURCE_EXHAUSTED` saat `jobs run` | Kuota sesaat. Script mengulang tiga kali; kalau masih gagal, tunggu semenit lalu jalankan `gcloud scheduler jobs run publisher-job --location=<region>`. |
| Proses pipeline mati sebelum job naik | Baca `~/gsp903/pipeline.log`. Biasanya Dataflow API belum siap — jalankan ulang script, resource yang sudah ada dilewati. |
| Job tidak muncul setelah 10 menit | Cek `gcloud dataflow jobs list --region=<region>` langsung; kadang job naik tepat setelah batas tunggu. |
| `samples/` kosong | Normal di menit-menit pertama. Window 2 menit, jadi file pertama muncul setelah dua window terisi. |
