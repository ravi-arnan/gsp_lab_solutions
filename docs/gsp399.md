# GSP399 - Design and Implement Network Security in Google Cloud: Challenge Lab

Runbook untuk [`gsp399.sh`](../gsp399.sh). Status: lolos uji syntax, shellcheck, dan dry-run harness.

## Kenapa lab ini cocok di-script

Semua task beroperasi pada level resource networking GCP (Cloud NGFW Global Network Firewall Policy, IAM Secure Tags, Cloud NAT Gateway, VPC Firewall Rules, dan VPC Flow Logs). Seluruh langkah dapat dieksekusi secara terotomasi via `gcloud` CLI tanpa interaksi manual di Web Console.

## Cara jalan

Jalankan perintah berikut di Cloud Shell:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp399.sh
bash gsp399.sh
```

Atau override parameter langsung jika diperlukan:

```bash
BASTION_IP="35.x.x.x" APP_SUBNET="app-subnet" bash gsp399.sh
```

Script otomatis mendeteksi project, IP external VM bastion, zona dan subnet VM, serta region Cloud Router. Jika dijalankan secara interaktif di terminal, script akan menampilkan prompt konfirmasi dengan nilai default hasil auto-detect.

## Detail Implementasi per Task

### Task 1: Migrasi Legacy Firewall Rules ke Global Policy
1. Membuat IAM Tag Key `unified-vpc-tags` dengan purpose `GCE_FIREWALL` pada network `unified-vpc`.
2. Mengekstrak network tags dari legacy rules (kecuali baseline egress rules) dan membuat IAM Tag Values.
3. Melakukan binding tag value ke VM yang menggunakan network tag terkait.
4. Menjalankan `gcloud beta compute firewall-rules migrate` dengan file tag mapping. Jika tool migrasi beta tidak menambahkan rules, script menyalin konfigurasi rules legacy secara langsung ke policy `unified-fw-policy`.
5. Mengasosiasikan policy `unified-fw-policy` ke VPC `unified-vpc`.
6. Mengubah urutan penegakan firewall network menjadi `BEFORE_CLASSIC_FIREWALL`.
7. Men-disable dan menghapus legacy rules yang sudah termigrasi (tetap mempertahankan baseline egress security rules).

### Task 2: Perbaiki Konfigurasi Cloud NAT
1. Mendeteksi subnet tempat `private-instance` berada (misal `client-subnet`).
2. Memperbarui Cloud NAT `unified-nat` pada Cloud Router `unified-router` agar mengarahkan mapping custom subnet ke subnet `private-instance`.
3. Memverifikasi resolusi DNS dan konektivitas internet dari `private-instance` melalui IAP tunnel.

### Task 3: Threat Containment dan Telemetry
1. Menambahkan tag `compromised-vm` pada VM target.
2. Membuat ingress firewall rule `containment-deny-http` (priority 100, DENY tcp:80, source 0.0.0.0/0, target-tags compromised-vm).
3. Membuat ingress firewall rule `allow-forensics-ssh` (priority 100, ALLOW tcp:22, source `<BASTION_IP>/32`, target-tags compromised-vm).
4. Mengaktifkan VPC Flow Logs pada application subnet.

## Troubleshooting

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| Bastion IP kosong saat ask | VM bastion belum selesai provisioning di Compute Engine | Tunggu 1-2 menit hingga instance bastion memiliki External IP, lalu jalankan ulang atau masukkan IP manual |
| Tag key creation error | Tag key sudah ada dari percobaan sebelumnya | Script secara otomatis mencari tag key yang sudah ada sebelum mencoba create |
| SSH ke private-instance timeout | IAP tunnel butuh beberapa detik untuk inisialisasi | Script mencoba retry hingga 3 kali; evaluasi lab tetap valid selama Cloud NAT subnet sudah ter-update |
