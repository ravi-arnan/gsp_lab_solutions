## Detail

1. **Task 5 tidak pakai Dataflow.** Lab menawarkan Dataflow, client library batch, atau insert manual. Dataflow butuh 12-16 menit plus manifest plus tambalan IAM (lihat [GSP1049](gsp1049.md)) — untuk 500 baris itu tidak sepadan. Script mengunduh CSV-nya lalu satu `batch.insert_or_update()`: 500 × 3 = 1.500 mutation, jauh di bawah batas 20.000 per commit, selesai dalam hitungan detik.
2. **`insert_or_update`, bukan `insert`.** Supaya script aman diulang tanpa ALREADY_EXISTS.
3. **Empat `CREATE TABLE` dikirim dalam satu `ddl update`.** Flag `--ddl` boleh diulang; semuanya jadi satu operasi, lebih cepat daripada empat panggilan terpisah.
4. **Kolom `Category.PortfolioInfo` ikut dibuat** sesuai spesifikasi Task 3, walaupun Task 4 tidak mengisinya. Grader memeriksa skema, jadi jangan dihilangkan.
5. **`Portfolio` baris 3 memakai ShortName `Insurance`, bukan `Ins`.** Berbeda dari GSP1050 — ikuti data challenge lab ini.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `429 Quota exceeded ... MutateRequestsPerMinutePerProject` dari `gcloud services enable` | Provisioning lab baru saja mengaktifkan banyak API. Spanner API sudah aktif, jadi script cuma mengeceknya dan tidak berhenti kalau enable gagal. Diamkan. |
| `instance config not found` | Region lab bukan `us-east1`. Jalankan ulang dengan `REGION=<region lab>`. |
| Checkpoint Create and Load Tables merah | Cek nama kolom dan tipenya persis seperti tabel di instruksi, termasuk `STRING(25)` untuk `ProductAssetCode` dan `ProductClass`. |
| `ModuleNotFoundError: google.cloud.spanner` | Script sudah mencoba `pip3 install`, dengan fallback `--break-system-packages`. Kalau tetap gagal, pakai venv lalu jalankan ulang. |
| `COUNT(*)` Customer kurang dari 500 | Unduhan CSV terpotong. Hapus `Customer_List_500.csv` lalu jalankan ulang. |
