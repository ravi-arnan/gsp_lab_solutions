# GSP499 - User Authentication: Identity-Aware Proxy

Runbook untuk [`gsp499.sh`](../gsp499.sh). Status: **belum diuji di lab sungguhan**.

Lab ini menyuruh menyalakan IAP dan menyalin JWT audience lewat Console. Keduanya punya padanan gcloud, jadi script tidak menyisakan langkah Console sama sekali.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp499.sh
bash gsp499.sh
```

Satu fase. **Tiga kali deploy from source**, masing-masing 2-3 menit, jadi total 8-10 menit.

## Checkpoint

| Task | Checkpoint | Isi |
|------|-----------|-----|
| 1 | Deploy a Cloud Run service | `1-HelloWorld` di `us-central1` |

## Dua langkah Console yang diganti gcloud

**Menyalakan IAP** — padanan toggle di halaman Identity-Aware Proxy:

```bash
gcloud beta run services update user-auth-lab --region=us-central1 --iap
```

Menyalakan IAP berarti IAP yang memanggil service, bukan publik lagi. Script karena itu mencabut `allUsers` dari `roles/run.invoker` dan memberikannya ke service agent IAP (`service-<PROJECT_NUMBER>@gcp-sa-iap.iam.gserviceaccount.com`). Service agent itu harus sudah ada dulu:

```bash
gcloud beta services identity create --service=iap.googleapis.com
```

**Memberi akses ke user** — padanan Add Principal + IAP-Secured Web App User:

```bash
gcloud beta iap web add-iam-policy-binding \
  --resource-type=cloud-run --service=user-auth-lab --region=us-central1 \
  --member=user:<akun student> --role=roles/iap.httpsResourceAccessor --condition=None
```

Perhatikan `--resource-type=cloud-run`; nilai `backend-services` yang lebih sering muncul di dokumentasi adalah untuk IAP di belakang load balancer, bukan IAP langsung di Cloud Run.

## JWT audience tidak perlu disalin dari Console

Lab menyuruh membuka menu tiga titik → **Get JWT audience code**. Tidak perlu: formatnya baku dan bisa disusun sendiri.

```
/projects/<PROJECT_NUMBER>/locations/<REGION>/services/<SERVICE_NAME>
```

Bentuk ini khusus Cloud Run. App Engine memakai `/projects/<NUM>/apps/<PROJECT_ID>`, load balancer memakai `/projects/<NUM>/global/backendServices/<ID>`.

## Yang sengaja tidak diikuti dari lab

Lab mematikan IAP di tengah Task 2 untuk mendemokan spoofing header lewat `curl`, lalu menyalakannya lagi di Task 3. Script membiarkan IAP menyala terus — mematikannya cuma bahan demonstrasi dan tidak ada checkpoint untuk itu. Kalau mau mencoba spoofing-nya sendiri, matikan IAP di Console lalu:

```bash
curl -X GET <URL> -H "X-Goog-Authenticated-User-Email: totally fake email"
```

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `gagal menyalakan IAP lewat gcloud` | Flag `--iap` butuh gcloud yang cukup baru. Nyalakan manual lewat Security > Identity-Aware Proxy, sisanya tetap otomatis. |
| Halaman "You don't have access" | Binding IAP butuh semenit. Tunggu, reload. |
| Masih ditolak setelah menunggu | Cookie IAP basi. Buka `<URL>/_gcp_iap/clear_login_cookie`, lalu **Use another account** dan login ulang dengan akun student. |
| Halaman menampilkan `None` untuk email dan ID | IAP mati, atau service agent IAP belum punya `roles/run.invoker`. |
| `Folder 1-HelloWorld tidak ditemukan` | Nama bucket tidak tertebak. Jalankan `gcloud storage ls` lalu `BUCKET=<nama> bash gsp499.sh`. |
| Deploy gagal di Cloud Build | Coba ulang; script idempoten dan akan melewati unduhan kode. |
