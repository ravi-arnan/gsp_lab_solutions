# GSP190 - IAM Custom Roles

Runbook untuk [`gsp190.sh`](../gsp190.sh). Status: **terverifikasi 100/100** (2026-08-07), keenam checkpoint diklik sekaligus di akhir.

Lab pengenalan, semua perintahnya sudah tertulis di instruksi dan tidak ada nilai yang diacak. Yang dikerjakan script cuma menjalankan sembilan task berurutan tanpa `nano`.

## Jalankan

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp190.sh | bash
```

Satu fase, sekitar satu menit. Tidak ada pertanyaan, tidak ada fase delete terpisah.

## Checkpoint

Enam checkpoint, semuanya otomatis, dan **semuanya bisa diklik sekaligus di akhir**:

| Task | Checkpoint | Efek script |
|------|-----------|-------------|
| 4 | Create a custom role using a YAML file | role `editor` dari `role-definition.yaml` |
| 4 | Create a custom role using flags | role `viewer` lewat `--permissions` |
| 6 | Update a custom role using a YAML file | `editor` + `storage.buckets.get/list` |
| 6 | Update a custom role using flags | `viewer` + `storage.buckets.get/list` via `--add-permissions` |
| 7 | Disabling a custom role | `viewer` stage `DISABLED` |
| 9 | Undeleting a custom role | `viewer` di-undelete |

Task 1, 2, 3, 5, dan 8 tidak dinilai. Task 1-3 cuma baca (`list-testable-permissions`, `roles describe`, `list-grantable-roles`) dan outputnya dipotong `head -n 30` supaya tidak membanjiri terminal. `list-testable-permissions` **tidak menerima `--limit`**, dan karena `set -o pipefail` aktif, SIGPIPE dari `head` dihitung gagal sehingga butuh `|| true`.

**Task 9 tidak membatalkan Task 7.** Undelete mengembalikan role ke keadaan sebelum dihapus, yaitu `DISABLED`, jadi checkpoint "Disabling a custom role" tetap hijau setelah script selesai. Karena itu tidak perlu berhenti di tengah untuk klik checkpoint.

## Yang diurus supaya idempoten

- `roles create` dilewati kalau role sudah ada — Role ID yang dihapus **tidak bisa dipakai ulang selama 37 hari**, jadi jangan sampai script mencoba create ulang setelah delete.
- Kalau run sebelumnya berhenti setelah Task 8, `viewer` ditemukan dalam keadaan `deleted: True` dan langsung di-undelete sebelum lanjut.
- `roles delete` dilewati kalau role sudah terhapus.
- Update Task 6a mengambil `etag` terbaru lewat `describe`, jadi tidak pernah bentrok dengan state sekarang.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `You do not have permission to access role` | Akun student bukan owner. Pastikan login pakai akun dari panel lab, bukan akun pribadi. |
| `Role editor already exists` | Script sudah pernah jalan. Aman, jalankan ulang — create-nya dilewati. |
| Checkpoint Task 9 merah | Undelete butuh beberapa detik terdeteksi. Tunggu, klik lagi. |
| `INVALID_ARGUMENT: Permission ... is not valid` | Salah ketik permission. Semua permission di script GA, jadi ini seharusnya tidak muncul. |
