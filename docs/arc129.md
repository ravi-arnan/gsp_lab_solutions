## Kenapa lab ini cocok di-script

bisa dibuat lewat `bq`/`gcloud`, walau walkthrough video-nya lewat Console.

## Detail task

### Task 1: Dataset + koneksi + IAM + external table

```bash
bq --location=US mk -d online_shop
bq mk --connection --location=US --project_id=$PROJECT_ID \
  --connection_type=CLOUD_RESOURCE user_data_connection
SERVICE_ACCOUNT=$(bq show --format=json --connection $PROJECT_ID.US.user_data_connection \
  | jq -r '.cloudResource.serviceAccountId')
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:$SERVICE_ACCOUNT" \
  --role=roles/storage.objectViewer
bq mkdef --autodetect \
  --connection_id=$PROJECT_ID.US.user_data_connection \
  --source_format=CSV gs://$PROJECT_ID-bucket/user-online-sessions.csv > /tmp/arc129_tabledef.json
bq mk --external_table_definition=/tmp/arc129_tabledef.json \
  --project_id=$PROJECT_ID online_shop.user_online_sessions
```

### Task 2: Policy tag ke kolom sensitif

Postingan konsolnya: ambil taxonomy + policy tag dari Data Catalog lalu pasang
di schema. CLI-nya:

```bash
TAXONOMY_NAME=$(gcloud data-catalog taxonomies list --location=us \
  --format="value(displayName)" --limit=1)
TAXONOMY_ID=$(gcloud data-catalog taxonomies list --location=us \
  --format="value(name)" --filter="displayName=$TAXONOMY_NAME" | awk -F/ '{print $6}')
POLICY_TAG=$(gcloud data-catalog taxonomies policy-tags list --location=us \
  --taxonomy="$TAXONOMY_ID" --format="value(name)" --limit=1)
```

Schema JSON di-update dengan `bq update --schema` menempelkan `$POLICY_TAG` ke
kolom `zip`, `latitude`, `ip_address`, dan `longitude` (fine-grained access).

### Task 3: Cabut akses USER 2

```bash
gcloud projects remove-iam-policy-binding $PROJECT_ID \
  --member="user:$USER_2" --role=roles/storage.objectViewer
```

## Checkpoint

- Task 1: Create a BigQuery dataset, connection, dan external table (BigLake)
- Task 2: Terapkan fine-grained access (policy tag) ke kolom sensitif
- Task 3: Hapus akses `storage.objectViewer` milik USER 2

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `service account tidak ketemu` | Koneksi BigQuery belum jadi atau lokasinya beda. Pastikan koneksi di lokasi `US` (multi-region) seperti dataset. |
| Schema update gagal | `$POLICY_TAG` kosong berarti taxonomy tidak ada di lokasi `us`. Cek `gcloud data-catalog taxonomies list --location=us`. |
| Binding USER 2 gagal dihapus | Lab hanya menandai benjol kalau binding sudah benar-benar hilang. Kalau script skip (USER_2 kosong), cek manual di IAM Console email user kedua. |
| `bq` bilang resource sudah ada | Idempoten, skip otomatis. |
