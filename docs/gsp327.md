# GSP327 - Engineer Data for Predictive Modeling with BigQuery ML: Challenge Lab

Runbook untuk [`gsp327.sh`](../gsp327.sh). Status: **terverifikasi 100/100** di lab sungguhan pada 2026-09-09.

Lab ini sepenuhnya BigQuery, tidak ada langkah Console. Script memakai REST API
(`gcloud auth print-access-token` + `curl` ke `bigquery.googleapis.com`), bukan CLI
`bq`, supaya pola helper `dbg()` / polling job konsisten dengan `gsp1281.sh`.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp327.sh
bash gsp327.sh
```

Script menanyakan nilai per-instance di awal (table name, fare amount column,
threshold trip_distance/fare/passenger, model name). Nilainya beda-beda per lab,
tergantung angka di panel lab. Isi persis yang tampil, contoh:

```bash
TABLE="taxi_training_data_141" FARE_COL="fare_amount_369" TRIP_DIST="2" \
FARE_MIN="2" PASS_MIN="2" MODEL="fare_model_628" bash gsp327.sh
```

## Checkpoint

| Task | Checkpoint |
|------|-----------|
| 1 | Create a cleaned copy of the data in `<table>` |
| 2 | Create BigQuery ML model `<model>` with RMSE 10 or less |
| 3 | Perform batch predictions and store in a new table `2015_fare_amount_predictions` |

## Yang tidak disalin mentah dari instruksi lab

- **Kolom target `fare_amount` dihitung, bukan disalin.** Lab minta
  `(tolls_amount + fare_amount)` digabung jadi kolom target, karena
  `total_amount` sudah termasuk tip.
- **Nama kolom dinormalisasi ke bentuk `report_prediction_data`.** Lat/lon
  di-alias `pickuplon`/`pickuplat`/`dropofflon`/`dropofflat` dan passenger_count
  menjadi `passengers`, supaya TRANSFORM dan prediksi cocok dengan bentuk data
  saat inferensi.
- **Filter geografi NYC.** Lon dibatasi -78..-70, lat 37..45. Ini menyelamatkan
  model dari koordinat outlier (0,0 dsb.).
- **Sampling `RAND() < 0.001`** untuk menekan >1 miliar baris jadi di bawah
  1 juta.
- **Model pakai `TRANSFORM(* EXCEPT(pickup_datetime), ...)`.** Hanya fitur yang
  ada di klausa TRANSFORM yang dipakai model; `ST_Distance(...) AS euclidean`,
  `dayofweek`, dan `hourofday` dihitung dari `pickup_datetime` di klausa itu,
  jadi `pickup_datetime` sendiri tidak perlu dikirim saat prediksi.

## REST API vs `bq`

Semua query dikirim ke `POST /v2/projects/{project}/queries` sebagai job async,
lalu dipoll lewat `GET /v2/projects/{project}/jobs/{jobId}`. Error maupun
`jobComplete: false` ditangani melalui helper `dbg()` dan `wait_job()` (maksimal
40 x 15 detik = 10 menit per query). Query yang butuh hasil (rowcount, RMSE)
diambil dari `GET /v2/projects/{project}/queries/{jobId}`.

## Idempoten

Aman diulang. `CREATE OR REPLACE TABLE` dan `CREATE OR REPLACE MODEL`
menimpa resource lama. Menunggu `historical_taxi_rides_raw` terisi 1-3 menit di
awal.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `403` / `PermissionDenied` saat query | Token expired atau akun salah. `gcloud auth login` ulang lalu jalankan lagi (token diambil per request). |
| Tabel `historical_taxi_rides_raw` belum ketemu | Lab baru saja import, tunggu sampai muncul di BigQuery UI. Script menunggu sampai 2 menit lalu lanjut; kalau gagal di SELECT, ulangi script. |
| Row count hasil bersih > 1 juta | Threshold di panel lab lebih longgar. Sampling `RAND()` deterministik tidak, jadi angka bisa beda tiap run. |
| RMSE > 10 | Fitur transform kurang kaya atau filter geografi terlalu longgar. Lab menerima linear_reg sederhana selama RMSE <= 10; transormasi `euclidean` + `dayofweek` + `hourofday` sudah cukup untuk dataset NY taxi. |
| `2015_fare_amount_predictions` tidak tercipta | Model gagal/tidak selesai di Task 2. Cek log `wait_job` di output. |

## Estimasi waktu

Training linear_reg di dataset jutaan baris biasanya 2-5 menit. Total script
sekitar 5-10 menit dari timer 15 menit.
