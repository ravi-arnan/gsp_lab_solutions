## Dua fase, dan alasannya

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp393.sh
bash gsp393.sh              # Task 1-6, 20-28 menit
```

## Rollback

Perintahnya bukan promote terbalik, melainkan:

```bash
gcloud deploy targets rollback cd-staging \
  --delivery-pipeline=web-app --release=web-app-001 \
  --rollout-id=rollback-001 --region=us-east1
```

`--release` menunjuk versi **tujuan** rollback, bukan versi yang sedang berjalan. `--rollout-id` sengaja diberi nama tetap supaya script bisa mengecek apakah rollback sudah pernah dijalankan — tanpa itu, mendeteksi idempotensi jadi rumit karena `cd-staging` sudah punya rollout web-app-001 yang lama dan sukses.

## Detail yang gampang salah

- **Nama rollout untuk approve diambil dari API**, bukan ditebak dari pola `web-app-001-to-cd-production-0001`. Nomor urutnya bertambah kalau promote pernah diulang.
- **`-q` di `releases promote`, `rollouts approve`, dan `targets rollback`** — ketiganya bertanya konfirmasi.
- **Menunggu tiap rollout `SUCCEEDED` sebelum langkah berikutnya.** Rollout pertama lama karena Cloud Deploy me-render manifest untuk semua target sekaligus saat release dibuat.
- **Perubahan `app.go` dicocokkan dari `fmt.Fprintf` ke kanan**, bukan lewat nomor baris, supaya indentasi tab file Go tetap utuh.
- Bullet ringkasan tantangan menyebut "tag with latest". Instruksi Task 6 sendiri hanya menyuruh build dan push, dan tidak ada checkpoint untuk tag, jadi script memakai perintah build yang sama seperti pertama.

## Idempoten

Aman diulang. Cluster, repository, release, dan rollout dicek dulu. `skaffold build` pertama dilewati kalau `web/artifacts.json` sudah ada; build kedua dilewati kalau release `web-app-002` sudah ada.

Kalau perlu membangun ulang dari nol: hapus `~/cloud-deploy-tutorials` lalu jalankan lagi.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Rollout `FAILED` di cd-staging | Namespace `web-app` belum ada di cluster itu, atau `clouddeploy.jobRunner` belum menempel. Jalankan ulang fase utama. |
| Promote ditolak | Rollout sebelumnya belum `SUCCEEDED`. Script sudah menunggu sendiri. |
| Rollout production tidak masuk `PENDING_APPROVAL` | Cek `requireApproval: true` ada di `clouddeploy-config/target-cd-production.yaml`. |
| `skaffold: command not found` | `gcloud components install skaffold`. |
| Checkpoint Task 6 merah setelah rollback dijalankan | Urutan terbalik. Nilai Task 6 hanya bisa didapat saat web-app-002 masih terpasang di cd-staging. |
