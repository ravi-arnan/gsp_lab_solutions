# GSP297 - Cloud Storage: Bucket Lock

Runbook untuk [`gsp297.sh`](../gsp297.sh). Status: belum diuji di lab sungguhan.

Lab 10 menit, 5 checkpoint, semuanya `gsutil`. Tidak ada parameter yang diacak, jadi script bisa dijalankan apa adanya.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp297.sh
bash gsp297.sh
```

Nama bucket = Project ID, mengikuti instruksi lab. Script butuh sekitar 1 menit karena ada beberapa jeda menunggu retention 10 detik lewat.

## Kenapa Task 6 tidak diotomasi

Task 6 (`gsutil rb`) tidak punya checkpoint sama sekali. Kalau bucket dihapus sebelum kamu klik **Check my progress**, checkpoint Task 1, 2, 3, dan 5 ikut merah karena grader mengecek state bucket, bukan riwayat perintah. Script berhenti sebelum `rb` dan mencetak perintahnya. Jalankan sendiri setelah semua checkpoint hijau — atau jangan sama sekali, skor tidak terpengaruh.

## Tiga hal yang bikin script polos gagal

1. **`gsutil retention lock` minta konfirmasi `[y|N]`.** Script pakai `echo y | gsutil retention lock`. Jangan pakai `yes |`, karena `yes` kena SIGPIPE dan `set -o pipefail` menganggap itu error.
2. **Melepas event-based hold me-reset retention expiration ke "sekarang + 10 detik".** Jadi `gsutil rm dummy_loan` langsung setelah release **selalu** 403. Helper `rm_when_expired()` mengulang sampai 5 kali dengan jeda 10 detik.
3. **Retention policy yang sudah dikunci tidak bisa dibatalkan.** Kalau script gagal di tengah setelah Task 3, bucket-nya tidak bisa dihapus sampai semua object lewat masa retensinya. Untuk lab dengan retensi 10 detik ini tidak masalah, tapi jangan pernah copy pola `retention lock` ini ke bucket sungguhan tanpa berpikir dua kali.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `AccessDeniedException: 403 ... under active Temporary hold` di Task 4b | **Ini yang diharapkan**, memang bagian dari lab. Script menelannya dengan `\|\| true`. |
| `Gagal menghapus ... setelah 5 percobaan` | Retention policy tidak sengaja diset lebih lama dari 10 detik. Cek `gsutil retention get gs://$PROJECT`. Kalau sudah terkunci, tunggu sampai durasinya lewat. |
| `BucketNameUnavailable` di Task 1 | Bucket dengan nama Project ID sudah dipakai orang lain (jarang). Ubah `BUCKET` di script. |
| Checkpoint Task 1/2/3/5 merah padahal script sukses | Bucket sudah terlanjur dihapus. Tidak bisa dibuat ulang dengan nama sama secara instan — jalankan ulang script dan klik checkpoint sebelum `rb`. |
