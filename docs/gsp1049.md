
## Detail

1. **Dataflow dijalankan lewat `gcloud dataflow jobs run`, bukan wizard Console.** Template yang sama: `gs://dataflow-templates/latest/GCS_Text_to_Cloud_Spanner`, manifest `gs://spls/gsp1049/manifest.json`, worker `e2-medium`. Script mem-polling `currentState` tiap 60 detik sampai `JOB_STATE_DONE`.
2. **Siklus `disable --force` lalu `enable` dataflow.googleapis.com justru merusak izin, dan script menambalnya.** Sesudah siklus itu binding service agent hilang, dan job yang diluncurkan langsung `JOB_STATE_FAILED` dalam semenit: *"The Dataflow service agent cannot access the worker service account."* Di lab manual jeda pemulihannya terisi waktu mengisi wizard Console. Script memasang sendiri `roles/dataflow.serviceAgent` untuk `service-<NUM>@dataflow-service-producer-prod`, `dataflow.worker` + `storage.objectAdmin` + `spanner.databaseUser` untuk worker SA, plus `iam.serviceAccountTokenCreator` service agent → worker SA, menunggu propagasi 60 detik, lalu retry job sampai 3×. Saat rerun siklusnya dilewati kalau API sudah aktif — kalau tidak, binding yang baru dipasang terhapus lagi.
3. **Backup pakai `--retention-period=365d`,** setara pilihan "1 year" di wizard Console (batas maksimum Spanner).
4. **Idempoten lewat jumlah baris.** Kalau `COUNT(*) > 1000`, script menganggap Dataflow sudah pernah sukses dan melewati Task 5 — menjalankan job dua kali akan gagal `ALREADY_EXISTS` di tengah jalan. Insert baris tunggal yang gagal karena duplikat cuma dicatat, tidak menghentikan script.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Job `JOB_STATE_FAILED` dalam <2 menit | Lihat log errornya: `gcloud beta dataflow logs list <JOB_ID> --region=<REGION> --importance=error` (`logs` cuma ada di track beta). Kalau soal service agent, script sudah menanganinya — jalankan ulang. |
| Job Dataflow `JOB_STATE_FAILED`, error soal worker tidak ter-provision | Kuota di regional endpoint itu habis. Ulangi dengan `DF_REGION=` region lain (lab menyarankan region US lain, misal `us-east1`). Job lama tidak perlu dihapus. |
| Checkpoint Task 3/4 merah padahal data ada | Lihat bagian jumlah baris di atas. |
| `Permission denied` saat menulis ke bucket | Bucket `gs://<PROJECT_ID>` dibuat script; kalau sudah ada milik project lain, hapus atau ganti nama di variabel `BUCKET`. |
| `ModuleNotFoundError: google.cloud.spanner` | Cloud Shell tanpa library-nya. Script sudah `pip3 install google-cloud-spanner`, kalau gagal jalankan manual lalu ulangi. |
| Backup lama sekali | Normal ~15 menit. Perintahnya menunggu sampai selesai; kalau sesi terputus, backup tetap jalan di server — cek `gcloud spanner backups list --instance=banking-instance`. |
