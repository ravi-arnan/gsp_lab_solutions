# GSP321 - Develop your Google Cloud Network: Challenge Lab

Runbook untuk [`gsp321.sh`](../gsp321.sh).

Challenge lab dengan skenario tim Griffin di Jooli Inc: membangun infrastruktur dev & prod VPC, dual-homed bastion host, instance Cloud SQL MySQL, cluster GKE 2 node, deployment WordPress dengan Cloud SQL Proxy sidecar, uptime check, dan akses IAM untuk engineer kedua.

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp321.sh
bash gsp321.sh
```

Atau one-liner:

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp321.sh | bash
```

Script akan otomatis mendeteksi akun Username 2 dari policy IAM project (`roles/viewer`). Cukup tekan Enter saat prompt konfirmasi muncul.

Lama eksekusi: ~ 8-12 menit (sebagian besar untuk alokasi Cloud SQL instance dan GKE cluster).

## Tabel Task

| Task | Otomatis | Keterangan |
|------|----------|------------|
| 1. Create development VPC manually | Ya | `griffin-dev-vpc` custom dengan 2 subnet: `griffin-dev-wp` (192.168.16.0/20) dan `griffin-dev-mgmt` (192.168.32.0/20) (Checkpoint) |
| 2. Create production VPC manually | Ya | `griffin-prod-vpc` custom dengan 2 subnet: `griffin-prod-wp` (192.168.48.0/20) dan `griffin-prod-mgmt` (192.168.64.0/20) (Checkpoint) |
| 3. Create bastion host | Ya | Instance `bastion` dual-homed ke `griffin-dev-mgmt` dan `griffin-prod-mgmt` beserta firewall rules SSH (Checkpoint) |
| 4. Create and configure Cloud SQL Instance | Ya | MySQL 8.0 `griffin-dev-db` di `us-central1`, database `wordpress`, dan user `wp_user` (`stormwind_rules`) (Checkpoint) |
| 5. Create Kubernetes cluster | Ya | GKE cluster `griffin-dev` 2 node `e2-standard-4` di subnet `griffin-dev-wp` zone `us-central1-b` (Checkpoint) |
| 6. Prepare the Kubernetes cluster | Ya | Manifests `wp-env.yaml` (PVC + secret database), SA key `key.json` untuk `cloud-sql-proxy`, dan secret `cloudsql-instance-credentials` (Checkpoint) |
| 7. Create a WordPress deployment | Ya | Patch `connectionName` ke `wp-deployment.yaml`, deploy `wp-service.yaml`, dan tunggu External IP (Checkpoint) |
| 8. Enable monitoring | Ya | Uptime check `wordpress-uptime-check` ke IP Load Balancer (Checkpoint) |
| 9. Provide access for an additional engineer | Ya | Berikan `roles/editor` ke Username 2 (Checkpoint) |

## Catatan

- **Bastion Dual-Homed**: Host bastion dipasang pada dua interface: nic0 di `griffin-dev-mgmt` dan nic1 di `griffin-prod-mgmt`, dengan tag `bastion` dan `ssh`.
- **WordPress Database Proxy**: File `wp-deployment.yaml` menggunakan sidecar `cloudsql-docker/gce-proxy` yang memerlukan argumen `-instances=<CONNECTION_NAME>=tcp:3306`. Script otomatis mengekstrak connection name via gcloud lalu melakukan substitusi string pada manifest sebelum `kubectl apply`.
- **Deteksi Otomatis Engineer Kedua**: Script memindai member IAM project untuk menemukan akun `student-*` kedua sehingga pengujian non-interaktif tetap dapat mengeksekusi Task 9 secara tuntas.
