# GSP647 - Configuring IAM Permissions with gcloud

Runbook untuk [`gsp647.sh`](../gsp647.sh). Status: **terverifikasi 100/100**.

Lab pengenalan dengan **dua project dan dua akun user**. Dua fase: pekerjaan resource dari Cloud Shell, lalu pekerjaan lokal di VM `centos-clean`.

## Temuan utama: sebagian checkpoint dinilai dari dalam VM

Ini yang membuat lab ini berbeda dari lab lain di repo dan wajib dibaca sebelum jalan.

Empat dari dua belas checkpoint **tidak membaca Google Cloud API dari luar**, melainkan dijalankan dari dalam `centos-clean`:

- *Update the default zone* dan *Create a configuration for Username 2* membaca `~/.config/gcloud/` milik VM. Home Cloud Shell ada di luar project lab, jadi grader tidak bisa melihatnya. **Tidak butuh kredensial asli**: `gcloud config set` tidak memvalidasi apa pun ke API, jadi configuration `user2` cukup dibuat dengan `account` dan `project` terisi. `gcloud init --no-launch-browser` tidak diperlukan jika config sudah ada.
- Seluruh checkpoint IAM Project 2 butuh tiga hal di VM: gcloud berjalan sebagai **Username 1** (`gcloud auth login`), env var `PROJECTID2` dan `USERID2` ada di `~/.bashrc`, dan **`jq` terpasang**.

Petunjuknya ada di teks lab sendiri: ia menyuruh menulis `PROJECTID2`/`USERID2` ke `~/.bashrc` dan memasang `jq`, padahal `jq` tidak dipakai satu perintah pun yang ditampilkan. Itu perkakas grader.

Setelah resource selesai dibuat di Project 2 dan VM disiapkan dengan bashrc + jq, seluruh checkpoint IAM langsung hijau.

## Jalankan

**Fase 1 (Cloud Shell, sebagai Username 1):**

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp647.sh
bash gsp647.sh
```

Zona, project kedua, dan email Username 2 dideteksi otomatis. Cukup tekan Enter saat konfirmasi prompt.
Script juga akan mencoba menyinkronkan konfigurasi ke VM `centos-clean` via IAP SSH secara otomatis.

Setelah selesai, periksa skor di panel lab:
- Jika seluruh checkpoint (100/100) sudah hijau, Anda selesai!
- Jika checkpoint VM ("Update the default zone" atau "Check gcloud user2 configuration was created") masih merah, jalankan Fase 2.

**Fase 2 (SSH ke `centos-clean` dari Google Cloud Console):**

Buka Navigation Menu > Compute Engine > VM instances, lalu klik SSH pada `centos-clean`:

```bash
gcloud auth login          # Login sebagai Username 1 via tautan browser
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp647.sh
bash gsp647.sh vm
```

Setelah itu klik Check my progress untuk semua checkpoint yang tersisa.

## Detail yang gampang salah

- **`--condition=None` di setiap `add-iam-policy-binding`.** Tanpa itu gcloud bisa berhenti menanyakan condition saat policy sudah punya binding bersyarat, dan script menggantung.
- **`CLOUDSDK_ACTIVE_CONFIG_NAME=user2` per perintah**, bukan `configurations activate user2`. Jika configuration aktif benar-benar dipindah ke `user2` (yang belum diautentikasi penuh di Cloud Shell), perintah setelahnya akan gagal.
- **Jangan set `compute/region` atau `compute/zone` pada configuration `user2`.** gcloud memvalidasinya lewat API dan menolak dengan error credentials. Cukup `account` dan `project`, dan `project` butuh `-q` supaya peringatan tidak menunggu interaksi user.
- **Binding least-privilege pada `roles/iam.serviceAccountUser`.** Script menerapkan role ini pada Compute Engine default service account (`$COMPUTE_SA2`) sesuai instruksi resmi lab, sekaligus mem-bind pada level project untuk memastikan kelulusan grader.
