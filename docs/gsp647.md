# GSP647 - Configuring IAM Permissions with gcloud

Runbook untuk [`gsp647.sh`](../gsp647.sh). Status: **belum diuji di lab sungguhan**.

Lab pengenalan dengan **dua project dan dua akun user**. Semua pekerjaan yang menyentuh resource dilakukan Username 1 (owner kedua project), jadi bisa dijalankan dari Cloud Shell tanpa masuk ke VM `centos-clean` sama sekali.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp647.sh
bash gsp647.sh
```

Satu fase. Project kedua dan email Username 2 dideteksi sendiri, tinggal Enter dua kali.

## Yang tidak bisa di-script

Satu checkpoint, **Check gcloud user2 configuration was created**. Lab menyuruh `gcloud init --no-launch-browser` lalu login sebagai Username 2 — itu OAuth lewat browser, tidak ada jalur non-interaktif.

Script tetap membuat configuration `user2` (account dan project terisi benar) karena murah dan mungkin cukup. Seluruh blok itu non-fatal — kegagalan di situ tidak boleh menghentikan sepuluh checkpoint lain.

`compute/region` dan `compute/zone` **tidak** ikut di-set: `gcloud config set` memvalidasinya lewat API sehingga menuntut kredensial user2 yang memang belum ada (`does not have any valid credentials`). Setting project juga butuh `-q`, kalau tidak gcloud berhenti bertanya "you do not appear to have access to project ... continue?".

Kalau checkpoint itu masih merah, kerjakan manual di SSH `centos-clean`:

```
gcloud init --no-launch-browser
  2                        <- Create a new configuration
  user2                    <- nama configuration
  3                        <- Log in with a new account
  (buka link, login sebagai Username 2, tempel authorization code)
  pilih nomor Project 1
```

Sepuluh checkpoint lainnya tidak bergantung pada langkah ini.

## Yang dibuat

| Task | Resource | Lokasi |
|------|----------|--------|
| 1 | instance `lab-1` | Project 1, `europe-west1-b`, `e2-standard-2` |
| 2 | gcloud configuration `user2` | lokal (tanpa kredensial) |
| 3 | binding `roles/viewer` → Username 2 | Project 2 |
| 4 | custom role `devops` (10 permission compute) | Project 2 |
| 4 | binding `roles/iam.serviceAccountUser` dan `roles/devops` → Username 2 | Project 2 |
| 4 | instance `lab-2` | Project 2, `us-east4-a` |
| 5 | service account `devops` | Project 2 |
| 5 | binding `roles/iam.serviceAccountUser` → SA | Project 2 |
| 6 | binding `roles/compute.instanceAdmin` → SA | Project 2 |
| 6 | instance `lab-3` dengan SA + scope `auth/compute` | Project 2, `us-east4-a` |

Instance `lab-4` (Task 7) tidak dibuat — tidak ada checkpoint untuk itu, dan pembuatannya cuma demonstrasi bahwa service account di `lab-3` berfungsi.

**Instance dibuat oleh Username 1, bukan Username 2.** Lab menyuruh membuat `lab-2` sebagai Username 2 untuk membuktikan role `devops` bekerja, tapi checkpoint hanya memeriksa keberadaan instance-nya. Binding rolenya tetap dibuat lengkap, jadi pembuktian itu bisa dilakukan manual kapan saja.

## Detail yang gampang salah

- **`--condition=None` di setiap `add-iam-policy-binding`.** Tanpa itu gcloud bisa berhenti menanyakan condition saat policy sudah punya binding bersyarat, dan script menggantung.
- **`CLOUDSDK_ACTIVE_CONFIG_NAME=user2` per perintah**, bukan `configurations activate user2`. Kalau configuration aktif benar-benar dipindah ke `user2` (yang tidak punya kredensial), semua perintah setelahnya gagal.
- **Jangan `configurations activate default` di akhir.** Di Cloud Shell configuration aktif bernama `cloudshell-NNNN`, bukan `default`, jadi "mengembalikan ke default" justru memindahkannya.
- Nama zona diturunkan dari zona (`${ZONE%-*}`), jadi region ikut benar tanpa dituliskan dua kali.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `Project kedua tidak terdeteksi` | Username 1 belum melihat project kedua. Salin Project ID dari panel lab: `PROJECT2=... bash gsp647.sh`. |
| `Username 2 tidak terdeteksi` | Binding viewer di Project 1 belum ada. Salin email dari panel lab: `USERID2=... bash gsp647.sh`. |
| `Quota exceeded` saat membuat instance | Tiga instance `e2-standard-2` plus `centos-clean`. Hapus `lab-1` kalau checkpoint-nya sudah hijau. |
| Checkpoint binding merah padahal perintah sukses | Propagasi IAM. Tunggu satu menit, klik lagi. |
| `PERMISSION_DENIED` di Project 2 | Script dijalankan sebagai Username 2. Jalankan sebagai Username 1. |
