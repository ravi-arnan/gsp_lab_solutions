# GSP521 - Secure Software Delivery: Challenge Lab

Runbook untuk [`gsp521.sh`](../gsp521.sh).

Challenge lab ini menggabungkan konfigurasi Artifact Registry, vulnerability scanning dengan On-Demand Scanning di Cloud Build, penandatanganan image dengan Binary Authorization Attestor dan KMS asymmetric signing key, penegakan policy attestation saat deploy ke Cloud Run, serta simulasi perbaikan vulnerability pada Dockerfile aplikasi.

## Cara jalan

Jalankan perintah one-liner langsung di terminal Cloud Shell:

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp521.sh | bash
```

Atau tentukan region secara eksplisit jika berbeda dengan default (`us-west1`):

```bash
REGION=us-west1 curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp521.sh | bash
```

Atau unduh terlebih dahulu dan jalankan:

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp521.sh
bash gsp521.sh
```

Durasi eksekusi: sekitar 10 sampai 14 menit (melibatkan empat build Cloud Build berurutan termasuk build custom builder `binauthz-attestation`).

## Tabel Task

| Task | Checkpoint | Otomatis | Keterangan |
|------|------------|----------|------------|
| 1 | Enable APIs and set up Artifact Registries | Ya | Enable API, unduh sample-app dari gs://spls/gsp521, dan buat repo `artifact-scanning-repo` serta `artifact-prod-repo` |
| 2 | Create a Cloud Build pipeline | Ya | Konfigurasi `cloudbuild.yaml` dasar untuk build dan push image `sample-image` ke repo scanning |
| 3 | Create an Attestor, KMS pair, and update the policy | Ya | Buat Container Analysis note `vulnerability_note`, Attestor `vulnerability-attestor`, KMS asymmetric key `lab-key`, dan update Binary Authorization policy REQUIRE_ATTESTATION |
| 4 | Integrate vulnerability scanning into your CI/CD pipeline | Ya | Build dan submit pipeline lengkap dengan step severity check (build ini sengaja gagal karena base image lama memiliki CVE CRITICAL) |
| 5 | Fix the vulnerability and redeploy the CI/CD pipeline | Ya | Update Dockerfile ke `python:3.12-slim` dengan dependensi baru (Flask 3.0.3, Gunicorn 23.0.0, Werkzeug 3.0.4), submit build ulang hingga sukses deploy ke Cloud Run |

Total: **100/100 poin** otomatis (5 checkpoint).

## Yang Perlu Diperhatikan

1. **Build Task 4 Sengaja Gagal:**
   Pada Task 4, build Cloud Build sengaja dirancang gagal di step `severity check` karena base image awal (`debian11` dengan Flask 1.1.4 dan Werkzeug 2.2.2) mengandung kerentanan tingkat CRITICAL. Kegagalan build ini adalah syarat kelulusan Checkpoint 4, bukan kegagalan script.

2. **Perbaikan Dockerfile Task 5:**
   Sesuai instruksi kurikulum terbaru, base image diperbarui ke `python:3.12-slim` dengan Flask 3.0.3, Gunicorn 23.0.0, dan Werkzeug 3.0.4.

3. **Attestation Ganda (Scanning dan Prod):**
   Attestation Binary Authorization terikat pada URL repository dan digest image. Script menandatangani image baik di repository scanning maupun di repository production sebelum di-deploy ke Cloud Run dengan opsi `--binary-authorization=default`.
