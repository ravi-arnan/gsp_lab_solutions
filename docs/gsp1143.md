# GSP1143 - Knowledge Catalog (Dataplex): Qwik Start - Console

Runbook untuk [`gsp1143.sh`](../gsp1143.sh). Status: terverifikasi 100/100 (2026-07-17).

## Peringatan utama

**Script ini dua fase, jangan digabung.** Task 4 menghapus lake, zone, dan asset yang dibuat Task 1 sampai 3. Kalau create dan delete dijalankan sekaligus, checkpoint task 1-3 gagal karena resource-nya sudah lenyap saat kamu klik Check my progress. Skor nyangkut di 25%.

**Region diisi dinamis per instance.** Di halaman lab tertulis `Region ____`. Default script `us-central1`, cocokkan dengan lab-mu.

## Sebelum jalan

1. Start lab, login akun student, buka Cloud Shell.
2. Catat Region dari tabel properti di Task 1.
3. Enable Cloud Dataplex API sudah ditangani script, tidak perlu manual.

## Jalankan

Download dulu, jangan pipe ke bash. `curl ... | bash -s create` membuat script dan stdin berebut, dan filenya tetap dibutuhkan untuk fase kedua.

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp1143.sh
```

**Fase 1** (Task 1, 2, 3). Ganti region sesuai lab-mu:

```bash
REGION=europe-west1 bash gsp1143.sh create
```

**Fase 2**: klik **Check my progress** untuk task 1, 2, dan 3 sampai **hijau semua**. Jangan lompat.

**Fase 3** (Task 4):

```bash
REGION=europe-west1 bash gsp1143.sh delete
```

Lalu klik Check my progress untuk task 4.

Lake butuh sampai 3 menit, zone sampai 2 menit. gcloud menunggu sampai selesai, jadi terlihat diam cukup lama. Itu normal.

## Yang dibuat

| Resource | ID | Display name | Catatan |
|----------|-----|--------------|---------|
| Lake | `sensors` | sensors | Task 1 |
| Zone | `temperature-raw-data` | temperature raw data | RAW, SINGLE_REGION, discovery on |
| Bucket | `<Project ID>` | - | Lab minta nama bucket = Project ID |

Asset sengaja dibuat tanpa flag discovery supaya inherit dari zone, sesuai instruksi lab.

## Yang harus muncul

Setelah fase `create`, tiga listing di akhir output harus menampilkan lake, zone, dan asset dengan state `ACTIVE`.

Setelah fase `delete`, listing lake harus kosong.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| Checkpoint task 1-3 merah setelah delete | Kamu menjalankan `delete` sebelum checkpoint hijau. Jalankan `create` lagi, klik checkpoint dulu, baru `delete`. |
| `NOT_FOUND` saat delete | Region salah. Resource dibuat di region lain. Cek `gcloud dataplex lakes list --location=<region>`. |
| Checkpoint merah padahal resource ada | Kemungkinan besar region tidak cocok dengan yang diminta lab. |
| `PERMISSION_DENIED` di dataplex | API belum aktif. Script sudah enable, tapi propagasinya bisa telat. Tunggu sebentar, jalankan ulang. |
| `HttpError 409 ... already exists` | Resource dari percobaan sebelumnya masih ada. Jalankan fase `delete` dulu, lalu `create` lagi. |

## Catatan

Detach asset **tidak** menghapus data di bucket. Bucket-nya tetap ada setelah fase delete, yang dilepas cuma pendaftarannya di lake. Itu memang perilaku yang benar menurut labnya.
