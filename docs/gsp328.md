## Jebakan yang sudah ditangani

### `BILLING_URL` wajib di frontend prod

`prod-frontend-billing/render.js` melempar `Error('BILLING_URL needs to be set.')` kalau env var itu kosong. Yang harus ditunjuk adalah **billing prod (Task 5)**, bukan private billing staging (Task 3) — instruksi lab justru menuliskan `PROD_BILLING_URL=$(gcloud run services describe private-billing-service-339 ...)`, yang isinya service Task 3. Salah tunjuk tidak menggagalkan deploy (env var mana pun membuat service start), tapi halaman UI-nya tidak akan menampilkan data billing, karena SA frontend hanya diberi `run.invoker` di service prod.

### Binding `run.invoker` di service, bukan project

Dipasang lewat `gcloud run services add-iam-policy-binding <billing-prod>`. Yang dinilai adalah frontend boleh memanggil billing tertentu; binding level project juga menghijaukan checkpoint tapi memberi akses ke semua service Cloud Run di project.

### Jeda setelah membuat service account

`gcloud run deploy --service-account` bisa ditolak dengan "Service account ... does not exist" kalau dipanggil langsung setelah `iam service-accounts create`. Script menunggu 10 detik.

### `require('node-fetch')` yang tidak ada di package.json

`prod-frontend-billing/index.js` baris 4 me-`require` `node-fetch`, tapi `package.json` tidak mencantumkannya. Container tetap start karena `google-auth-library@9` → `gaxios@6` menarik `node-fetch@2` dan npm menaruhnya di `node_modules` teratas. Kalau suatu saat dependency itu berubah (gaxios 7 memakai `fetch` bawaan Node), Task 7 akan gagal dengan `MODULE_NOT_FOUND`. Perbaikannya satu baris:

```bash
sed -i "/require('node-fetch')/d" ~/pet-theory/lab07/prod-frontend-billing/index.js
```

Variabelnya memang tidak pernah dipakai. Script belum melakukannya supaya source lab tidak diubah tanpa perlu — kalau deploy Task 7 gagal saat start, jalankan `sed` di atas lalu ulangi `bash gsp328.sh prod`.

## Idempoten

Aman diulang. `gcloud run deploy` menimpa revisi, service account dilewati kalau sudah ada, binding IAM idempoten, repo di `~/pet-theory` dipakai ulang. Penghapusan service Task 1 dilewati kalau sudah tidak ada.

## Kalau gagal

- **Build lama atau gagal push** — pastikan `containerregistry.googleapis.com` dan `artifactregistry.googleapis.com` aktif (script sudah `enable`, tapi propagasinya butuh puluhan detik pada project baru). Ulangi fase yang sama.
- **Checkpoint Task 1 merah setelah fase prod jalan** — service-nya sudah dihapus. Deploy ulang dengan `bash gsp328.sh` (fase staging), tunggu hijau, baru jalankan fase prod lagi; fase prod idempoten.
- **HTTP 403 saat probe service private** — normal kalau `gcloud auth print-identity-token` gagal; jalankan `gcloud auth login` di Cloud Shell lalu ulangi. Checkpoint tetap hijau selama service-nya ada dan authenticated.
- **Region salah** — semua service ikut `REGION`. Lab default `us-east4`; kalau panel menampilkan zone (`us-east4-b`), isi region-nya tanpa sufiks huruf.
