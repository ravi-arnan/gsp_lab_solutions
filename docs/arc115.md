# ARC115 - Monitoring in Google Cloud: Challenge Lab

Kelima checkpoint otomatis. VM `apache-vm` sudah disiapkan lab; zone-nya dicari
sendiri oleh script.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/arc115.sh
bash arc115.sh
```

## Task

| Task | Otomatis | Catatan |
|------|----------|---------|
| 1. Install Ops Agent | Ya | config apache metrics + apache_access/apache_error logging |
| 2. Uptime check | Ya | resource type `uptime_url`, host = External IP VM |
| 3. Alert policy | Ya | `workload.googleapis.com/apache.traffic`, ALIGN_RATE, > 3000 |
| 4. Dashboard + 2 chart | Ya | REST `v1/dashboards`: CPU load (1m) dan Apache Requests |
| 5. Log-based metric | Ya | `logName=".../logs/apache-access" AND textPayload:"200"` |

## Catatan

- **"3 KiB/s" diterjemahkan jadi threshold 3000**, mengikuti konvensi
  [gsp1108](gsp1108.md) yang menyebut "4 KiB/s" dengan threshold value 4000 di
  instruksinya sendiri. Bukan 3072.
- **Notification channel email tidak dibuat** — sudah tiga lab berturut
  (gsp089, gsp1108, arc115) checkpoint alert policy hijau tanpa itu.
- Dashboard memakai API `v1` (`monitoring.googleapis.com/v1/projects/*/dashboards`),
  berbeda dari uptime check dan alert policy yang di `v3`.
- Trafik 120 detik digenerate di akhir Task 1 sehingga metrik Apache sudah ada
  datanya sebelum dashboard dan alert dibuat.
