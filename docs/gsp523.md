# GSP523 - Implement Multimodal Vector Search with BigQuery: Challenge Lab

Runbook untuk [`gsp523.sh`](../gsp523.sh). Status: **terverifikasi 100/100** (2026-08-22), keempat checkpoint hijau sekali jalan.

## Cara jalan

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp523.sh | bash
```

Satu pertanyaan saja (frasa pencarian Task 4, default `Men Sweaters`), sisanya dideteksi sendiri. Semua task otomatis, tidak ada langkah Console.

| Task | Otomatis | Cara |
|------|----------|------|
| 1 Connection + IAM | ya | `bq mk --connection --connection_type=CLOUD_RESOURCE vector_conn` + tiga binding ke SA yang dibuat connection |
| 2 Object table | ya | `CREATE OR REPLACE EXTERNAL TABLE ... object_metadata='SIMPLE', uris=['gs://<project>/*']` |
| 3 Model + embedding | ya | model remote `endpoint='multimodalembedding@001'`, lalu `ML.GENERATE_EMBEDDING(MODEL, TABLE <object table>)` |
| 4 Vector search | ya | `VECTOR_SEARCH(..., top_k => 2, distance_type => 'COSINE')` |

## Nama dan region dideteksi, bukan ditanya

Dataset bawaan lab (`gcc_bqml_dataset`) dicari lewat `bq ls` dengan pola `*bqml_dataset`. Dari situ diambil dua hal:

- **Lokasinya** (`bq show --format=json | jq .location`) jadi region connection. Ini bukan kosmetik: connection yang regionnya beda dari dataset ditolak dengan `Not found: Connection` saat object table dibuat. Instruksi lab menyebut `us-east4`, tapi mengikuti dataset lebih aman kalau varian lab memakai region lain.
- **Prefiksnya** (`gcc`) jadi dasar nama `<prefix>_image_object_table`, `<prefix>_embedding`, `<prefix>_retail_store_embeddings`, `<prefix>_vector_search_table`. Kelima nama di lab ini memang seprefiks.

Kalau tebakan itu meleset, timpa satu per satu:

```bash
DATASET=... CONN=... OBJECT_TABLE=... MODEL=... EMBED_TABLE=... SEARCH_TABLE=... \
REGION=... BUCKET=... TOP_K=2 bash gsp523.sh
```

## Jebakan yang sudah ditangani

### Service account connection tidak bisa ditebak

`bq mk --connection` membuat service account dengan ID acak (`bqcx-...@gcp-sa-bigquery-condel.iam.gserviceaccount.com`). Script membacanya balik lewat `bq show --connection --format=json | jq -r .cloudResource.serviceAccountId` — jangan dihardcode.

Role "Agent Platform User" di instruksi lab adalah nama baru **`roles/aiplatform.user`** (dulu Vertex AI User); yang dua lagi `roles/bigquery.dataOwner` dan `roles/storage.objectViewer`.

### Jeda 60 detik setelah binding IAM

Binding ke SA connection tidak langsung berlaku. Tanpa jeda, `CREATE EXTERNAL TABLE` gagal dengan permission denied ke bucket, atau `ML.GENERATE_EMBEDDING` gagal memanggil Vertex. 60 detik cukup di percobaan sejauh ini.

### Hitungan baris embedding dicetak

`ML.GENERATE_EMBEDDING` tidak melempar error kalau sebagian gambar gagal — barisnya tetap masuk dengan `ml_generate_embedding_status` terisi. Script mencetak `baris` dan `gagal` supaya Task 4 yang kosong bisa langsung dilacak ke sini, bukan ke sintaks `VECTOR_SEARCH`.

### Kolom query `VECTOR_SEARCH` tidak disebut

Template lab tidak mengisi `query_column_to_search`. Itu memang boleh: BigQuery menyimpulkannya kalau subquery hanya punya satu kolom, dan di sini subquery-nya `SELECT ml_generate_embedding_result AS embedding_col`. Menambah kolom lain ke subquery itu akan mematahkannya.

## Idempoten

Aman diulang. Connection dilewati kalau sudah ada, binding IAM idempoten, semua tabel dan model pakai `CREATE OR REPLACE`. Menjalankan ulang membangkitkan ulang embedding (memanggil model lagi) — bukan masalah selain waktu.

## Kalau gagal

- **`Dataset *_bqml_dataset tidak ketemu`** — lab belum selesai provisioning, atau nama datasetnya lain. Cek `bq ls`, lalu ulangi dengan `DATASET=<nama>`.
- **`Not found: Connection`** — region connection beda dari dataset. Hapus connection lama (`bq rm --connection --location=<region> vector_conn`) dan ulangi.
- **Permission denied saat object table** — propagasi IAM belum selesai. Ulangi script; bagian Task 1 dilewati dan jedanya berjalan lagi.
- **`gagal` > 0 di ringkasan embedding** — bucket berisi file yang bukan gambar/video. Batasi `uris` ke pola yang lebih sempit lewat `BUCKET=<project>/images` atau ubah query object table.
