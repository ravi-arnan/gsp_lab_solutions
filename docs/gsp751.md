# GSP751 — Interact with Terraform Modules

Lab intermediate Terraform di Google Cloud: menggunakan module dari Terraform Registry dan membuat custom module lokal untuk Cloud Storage static website.

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp751.sh
bash gsp751.sh
```

Atau one-liner langsung dengan region spesifik (misalnya `us-central1`):

```bash
REGION=us-central1 curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp751.sh | bash
```

## Task

| Task | Isi | Checkpoint | Otomatis |
|------|-----|-----------|----------|
| 1 | Use modules from the Registry | **50 poin** | ya (clone repo network, apply VPC, destroy VPC) |
| 2 | Build a module | **50 poin** | ya (modul gcs-static-website-bucket, apply, upload HTML) |

Total: **100/100 poin** otomatis.

## Yang perlu diperhatikan

**Deteksi dummy wrapper Terraform di Cloud Shell:**
Pengecekan instalasi memeriksa string output `terraform --version | grep 'Terraform v'`. Jika belum terpasang atau masih berupa dummy wrapper bawaan Google Cloud Shell, script otomatis menginstal Terraform dari repositori HashiCorp.

**Task 1 vs Task 2:**
- Task 1 mem-provision VPC `example-vpc` menggunakan module `terraform-google-modules/network/google` v6.0.1, lalu membersihkannya (`terraform destroy`) sesuai instruksi lab. Checkpoint Task 1 tetap valid (50 poin).
- Task 2 mem-provision Cloud Storage bucket `gs://$PROJECT_ID` menggunakan module lokal `modules/gcs-static-website-bucket` dan mengunggah `index.html` serta `error.html`. Script sengaja membiarkan bucket tetap aktif hingga akhir agar verifikasi Task 2 tidak gagal.

**Idempotensi:**
Jika bucket `gs://$PROJECT_ID` sudah terlanjur dibuat di GCP namun belum ada di Terraform state, script otomatis melakukan `terraform import` sebelum apply untuk mencegah error HTTP 409 conflict.
