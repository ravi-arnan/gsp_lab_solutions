## Nilai yang dideteksi sendiri

| Nilai | Sumber |
|-------|--------|
| Nama instance Cloud SQL | `gcloud sql instances list` (instance pertama) |
| Region | `sql instances describe --format='value(region)'` |
| DNS record | `value(dnsName)`, fallback `value(dnsNames[0].name)` |
| Nama DNS zone | `<region>.sql.goog.` |
| Service attachment URI | `value(pscServiceAttachmentLink)` |
| Zone `cloudsql-client` dan `vm2-vpc2-ncc` | `compute instances list` |

Nama VPC (`vpc1-ncc`, `vpc2-ncc`), subnet (`vpc2-ncc-subnet1`), dan exclude range (`10.1.2.0/24`, `10.3.3.0/24`) tetap dari instruksi lab, tapi bisa ditimpa lewat env var `EXCLUDE1` / `EXCLUDE2`.

## Pemilihan IP untuk endpoint PSC

Lab menyuruh "pilih IP bebas di CIDR subnet" dan memperingatkan soal error `IP is already being used`. Script memilih dari **ujung atas** CIDR (GCP memberi IP VM dari ujung bawah dan mereservasi dua IP terakhir), lalu mencoba `addresses create` satu per satu sampai berhasil — enam kandidat, mundur dari `x.x.x.252`. Kalau mau menentukan sendiri: `PSC_IP=10.3.3.240 bash gsp1317.sh`.

## Task 5 tanpa psql interaktif

SQL dikirim ke `cloudsql-client` sebagai base64 lewat `gcloud compute ssh --command`, jadi tidak ada escaping berlapis dan tidak ada prompt password (`PGPASSWORD=changeme`). Isinya idempoten:

- `CREATE DATABASE company;` — kegagalan "already exists" diabaikan (Postgres tidak punya `IF NOT EXISTS` untuk database).
- `CREATE TABLE IF NOT EXISTS employees ...`
- INSERT dibungkus `WHERE NOT EXISTS (SELECT 1 FROM employees)` supaya rerun tidak menggandakan baris.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `DNS name Cloud SQL tidak terbaca` | Instance belum selesai provisioning atau PSC belum aktif. Tunggu, ulangi. |
| `Service attachment Cloud SQL kosong` | Sama seperti di atas. |
| Semua kandidat IP terpakai | Set `PSC_IP=` manual dari CIDR subnet, hindari IP internal `vm2-vpc2-ncc` dan `cloudsql-client`. |
| `pscConnectionStatus` bukan `ACCEPTED` | Butuh beberapa detik. Jalankan ulang perintah describe-nya. |
| psql `could not translate host name` | DNS zone belum menyebar atau record salah IP. Cek `gcloud dns record-sets list --zone=cloudsql-dns`. |
| SSH ke `cloudsql-client` gagal | Firewall IAP. Cek `gcloud compute firewall-rules list`, lab biasanya sudah menyediakan. |
