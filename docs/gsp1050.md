## Detail

1. **Task 1 pakai `gcloud spanner databases execute-sql`, bukan Spanner Studio.** DML yang sama persis, hasilnya identik untuk grader.
2. **Task 2-5 tetap memakai `snippets.py` bawaan lab** (di-`wget` dari `storage.googleapis.com/cloud-training/OCBL373/`). Fungsi-fungsinya yang diminta lab: `insert_data`, `query_data`, `add_column`, `update_data`, `add_index`, `add_storing_index`, dan pembacaannya.
3. **`python3`, bukan `python`.** Instruksi lab menulis `python`; Cloud Shell tidak selalu punya alias itu.
4. **`pip install` punya fallback `--break-system-packages`.** Python yang dikelola sistem menolak install global (PEP 668) di rilis Cloud Shell yang lebih baru.
5. **Idempoten.** Insert ulang, `ADD COLUMN` ulang, dan `CREATE INDEX` ulang semuanya gagal dengan ALREADY_EXISTS/duplicate — ditangkap dan dianggap "sudah pernah jalan", script lanjut.
6. **Noise metrik dimatikan** lewat `SPANNER_DISABLE_BUILTIN_METRICS=true`; tanpa itu tiap panggilan client library memuntahkan error 400 Cloud Monitoring yang tidak ada hubungannya dengan hasil.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `Table not found: Portfolio` | Instance/database lab belum selesai dibuat. Tunggu sebentar, jalankan ulang. |
| `snippets.py: No such file` | `wget` gagal (jaringan). Ulangi, script memakai `-N` jadi tidak mengunduh dua kali. |
| `externally-managed-environment` dari pip | Sudah ada fallback `--break-system-packages`. Kalau tetap gagal, buat venv: `python3 -m venv ~/venv && source ~/venv/bin/activate` lalu jalankan ulang. |
| Checkpoint Task 5 merah | Backfill index butuh waktu. Tunggu semenit lalu klik lagi. |
