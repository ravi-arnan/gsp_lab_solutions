# GSP1024 - Using Prometheus for Monitoring on Google Cloud: Qwik Start

Runbook untuk [`gsp1024.sh`](../gsp1024.sh). Status: **diuji sekali,
50/100** (2026-10-04, europe-west1) — Task 1 & 3 hijau, Task 4 & 5 merah
walau semua resource terverifikasi benar. Lihat "Hasil uji" di bawah.

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp1024.sh
bash gsp1024.sh
```

Dua pertanyaan di awal kalau dijalankan dari terminal: `REGION` (default
`europe-west1`) dan `ZONE` (default `europe-west1-b`). Instruksi lab mengunci
keduanya, jadi tekan Enter saja kecuali panel lab-mu menyebut yang lain. Kalau
dijalankan lewat `curl ... | bash`, script langsung memakai default.

Lama ~15 menit, hampir semuanya menunggu cluster GKE dan LoadBalancer.

| Task | Otomatis | Cara |
|------|----------|------|
| 1 Docker repository | ya | `gcloud artifacts repositories create` + `docker load/tag/push` |
| 2 Cluster GKE | ya | `gcloud beta container clusters create --enable-managed-prometheus` |
| 3 Namespace | ya | `kubectl create ns gmp-test` |
| 4 Aplikasi Flask | ya | manifest ditulis sendiri, apply, tunggu LoadBalancer, bebani app |
| 5 Dashboard | ya | `gcloud monitoring dashboards create` |

Empat checkpoint, semuanya otomatis: **Create a Docker repository**,
**Check if Prometheus has been deployed** (namespace `gmp-test`),
**Check if the Flask application has been deployed**, **Check if the dashboard
is created**. Tidak ada langkah Console yang wajib.

## Manifest ditulis sendiri, bukan `unzip` + `nano`

Instruksi lab mengunduh `gmp_prom_setup.zip` lalu menyuruh mengganti
`<ARTIFACT REGISTRY IMAGE NAME>` di `flask_deployment.yaml` lewat nano. Script
menulis ketiga manifest itu langsung (Deployment `helloworld-gke`, Service
`hello`, PodMonitoring `prom-example`) dengan image sudah tersulam. Alasannya:
tanpa editor interaktif, dan `kubectl apply` jadi idempoten di run ulang.

Isi manifest disamakan dengan zip aslinya, termasuk `containerPort: 4000` bernama
`flaskport` (nama port inilah yang di-scrape PodMonitoring).

## Poin yang rawan

- **`docker load` butuh image sumber dulu.** Script memuat
  `flask_telemetry.tar` dari `flask_telemetry.zip` sebelum `docker tag`. Kalau
  image `gcr.io/ops-demo-330920/flask_telemetry:...` sudah ada di docker lokal,
  unduhan dilewati.
- **Login docker ke Artifact Registry.** `gcloud auth configure-docker
  europe-west1-docker.pkg.dev` dijalankan supaya `docker push` tidak ditolak
  401. Instruksi lab tidak menyebutnya karena Cloud Shell biasanya sudah
  terkonfigurasi.
- **`--enable-managed-prometheus` tidak bisa diandalkan dari `describe`.**
  Kalau cluster sudah ada tapi dibuat tanpa flag itu, script menjalankan
  `clusters update --enable-managed-prometheus` (pelajaran GSP510/GSP364).
- **Dashboard dibuat sekali saja.** Sebelum create, script mencari dashboard
  dengan `displayName="Prometheus Dashboard Example"`. Kalau ada, create
  dilewati supaya tidak menumpuk dashboard kembar.
- **Metrik baru muncul beberapa menit setelah aplikasi dibebani.** Checkpoint
  Task 4 memeriksa Deployment/Service, bukan grafiknya, jadi tidak perlu
  menunggu metrik. Dashboard tetap dibuat walau grafiknya masih kosong.

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `docker push` 401/denied | `gcloud auth configure-docker ${REGION}-docker.pkg.dev --quiet`, lalu ulangi. |
| IP LoadBalancer tidak keluar | Tunggu; script menunggu sampai 30 x 20 detik. Cek `kubectl -n gmp-test get svc hello`. |
| `curl: (7)` ke `/metrics` | Pod belum `Running` atau service belum dapat IP. `kubectl -n gmp-test get pods,svc`. |
| Checkpoint Task 1 merah | Repository `docker-repo` harus ada di `europe-west1`. Cek `gcloud artifacts repositories list --location=europe-west1`. |
| Dashboard tidak muncul | `gcloud monitoring dashboards list --filter='displayName="Prometheus Dashboard Example"'`. |

Sementara belum ada bukti lain, perlakuan aman untuk percobaan berikutnya:

1. Jalankan script, tunggu sampai muncul baris `Metrik sudah ter-ingest ke Cloud
   Monitoring` (script sekarang polling sampai 5 menit).
2. Klik Task 4 dan Task 5, lalu **tunggu 5-10 menit** dan klik lagi kalau masih 0.
   Jangan buru-buru End Lab.
3. Hard refresh halaman lab (Ctrl+Shift+R) kalau status tetap 0 — status
   checkpoint kadang ke-cache di tab.
4. Buka dashboard-nya di Console (Monitoring → Dashboards → Prometheus Dashboard
   Example) sesuai instruksi lab.

Kalau percobaan berikutnya tetap merah padahal resource persis seperti tabel di
atas, berarti masalahnya di sisi grader lab, bukan di script.
