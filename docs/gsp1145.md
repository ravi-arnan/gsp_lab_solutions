# GSP1145 - Create and Add Aspects to Knowledge Catalog Assets

Runbook untuk [`gsp1145.sh`](../gsp1145.sh). Status: terverifikasi 100/100 di `us-east1` (2026-08-06); sebelumnya juga hijau di region dinamis (2026-07-17).

## Peringatan utama

**Cek region dulu.** Versi lab per 2026-08 menulis `us-east1` eksplisit di Task 1 dan Task 2 (dan itu default script sekarang). Instance lama mengisinya dinamis (`Region ____` / `Location ____`). Keduanya nilai yang sama; cocokkan dengan halaman lab-mu.

**Task 3 bagian paling rapuh.** Task 1 dan 2 pakai flag `gcloud` yang terverifikasi dari dokumentasi resmi. Task 3 harus menempelkan aspect ke entry BigQuery, dan **dokumentasi resmi tidak pernah menyebut format nama entry BigQuery**. Script menanganinya dengan mencari entry-nya, bukan mengarang nama. Kalau tetap gagal, ada jalur UI di bawah.

## Sebelum jalan

1. Start lab, login akun student, buka Cloud Shell.
2. Catat Region dari tabel properti Task 1.
3. Dataset `customers` disiapkan lab, bukan script. Kalau belum muncul, tunggu provisioning.

|----------|-----|--------------|---------|

## Troubleshooting

| Gejala | Sebab dan solusi |
|--------|------------------|
| `dataset 'customers' belum ada` | Resource pre-created lab belum siap. Tunggu, refresh halaman lab, jalankan ulang. |
| `entry untuk customer_details tidak ketemu` | Dataplex butuh waktu meng-index tabel BigQuery. Tunggu beberapa menit, jalankan ulang. Kalau tetap gagal, pakai jalur UI di bawah. |
| Location dataset beda dengan REGION | REGION salah. Cocokkan dengan halaman lab. |
| Aspect type gagal dibuat, error soal `index` | `enumValues` di template pakai index 1 dan 2. Kalau API menolak, coba ubah ke 0 dan 1 di `gsp1145.sh`. |
| `INVALID_ARGUMENT` di `entries update` | Format aspect key kemungkinan tidak cocok. Cek key yang tercetak sebelum perintah jalan, bandingkan dengan `PROJECT.LOCATION.ASPECT_TYPE@Schema.KOLOM`. |
| Checkpoint "Add an aspect to assets" merah | Butuh beberapa menit sebelum checkpoint mendeteksi. Tunggu, klik lagi. |

## Fallback: Task 3 lewat UI

Kalau bagian aspect gagal, Task 1 dan 2 tetap terpakai. Sisanya cuma beberapa klik:

1. Menu kiri, **Discover > Search**.
2. **Filters > Systems**, centang **BigQuery**, klik OK.
3. Ketik `customer_details`, klik hasilnya.
4. Scroll ke **Aspects**, di sebelah **Optional aspects** klik **Add**.
5. Ketik `protected data aspect`, pilih **Protected Data Aspect**.
6. **Protected Data Flag** pilih **Yes**, klik **Save**.
7. Buka tab **Schema**, centang 9 kolom: `zip`, `state`, `last_name`, `country`, `email`, `latitude`, `first_name`, `city`, `longitude`.
8. Klik **Add aspect** > **Protected Data Aspect**, pilih **Yes**, klik **Save**.

## Catatan teknis

Entry BigQuery dibuat otomatis Dataplex di entry group `@bigquery`, dan **letaknya mengikuti location dataset-nya, bukan region lake**. Karena itu script mendeteksi location dataset lewat `bq show` dan memakainya untuk `entries update`, sementara aspect key tetap memakai region tempat aspect type dibuat. Dua hal ini bisa berbeda, dan itu sumber kegagalan paling mungkin di lab ini.

## Bug yang sudah diperbaiki: `@Schema.181`

Versi pertama memakai nama variabel `COLUMNS` untuk daftar kolom. Itu **variabel spesial bash** yang berisi lebar terminal. Bash me-reset-nya lewat `checkwinsize`, dan assignment skalar ke variabel array menulis ke **index 0**, sehingga `zip` diam-diam berubah jadi angka lebar terminal:

```
"...@Schema.181": { ... }      <- harusnya @Schema.zip
"...@Schema.state": { ... }    <- sisanya utuh
```

Errornya muncul sebagai `400 Aspect path 'Schema.181' is used but not provided by any Aspect`.

Bug ini lolos tes lokal karena tanpa TTY bash tidak pernah me-reset `COLUMNS`, dan cuma muncul di Cloud Shell yang punya terminal sungguhan. Variabelnya sekarang bernama `ASPECT_COLUMNS`, dan script punya guard yang berhenti kalau ada nama kolom berubah jadi angka.

Pelajarannya: jangan pakai `COLUMNS`, `LINES`, `RANDOM`, `SECONDS`, `PWD`, `IFS`, atau `REPLY` sebagai nama variabel sendiri.
