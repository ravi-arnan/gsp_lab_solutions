# GSP329 - Use Machine Learning APIs on Google Cloud: Challenge Lab

Runbook untuk [`gsp329.sh`](../gsp329.sh). Status: **terverifikasi 100/100** (2026-08-10), semua checkpoint hijau. Dry-run harness berhenti di langkah Python karena stub `gcloud` tidak menghasilkan `key.json` sungguhan — itu batas harness, bukan bug script.

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp329.sh
bash gsp329.sh
```

Satu pertanyaan di awal: nama bucket berisi gambar, defaultnya sama dengan project ID (itu yang dipakai lab). Kalau berbeda:

```bash
BUCKET=<nama-bucket> bash gsp329.sh
```

Semua task otomatis, tidak ada langkah Console.

| Task | Poin | Otomatis | Cara |
|------|------|----------|------|
| 1 Service account + role | 25 | ya | `gcloud iam service-accounts create ml-dev` + binding `roles/bigquery.dataEditor`, `roles/storage.admin` |
| 2 Credential JSON | 25 | ya | `gcloud iam service-accounts keys create ~/key.json` + `GOOGLE_APPLICATION_CREDENTIALS` |
| 3 Ekstraksi teks | 10 | ya | Vision `document_text_detection`, hasilnya diunggah sebagai `<nama>.txt` ke bucket yang sama |
| 4 Terjemahan + BigQuery | 20 | ya | Translation v2 `target_language='fr'`, baris masuk ke `image_classification_dataset.image_text_detail` |
| 5 Query per locale | 20 | ya | `bq query` `GROUP BY locale ORDER BY lcount DESC` |

## Jebakan: dua role dari instruksi lab tidak cukup

Instruksi hanya menyebut `roles/bigquery.dataEditor` dan `roles/storage.admin`. Dengan tepat dua role itu, panggilan Storage pertama dari script Python langsung 403 (terbukti 2026-08-10):

```
403 GET https://storage.googleapis.com/storage/v1/b/<bucket>/o:
ml-dev@<project>.iam.gserviceaccount.com does not have serviceusage.services.use
access to the Google Cloud project.
```

Penyebabnya klien Python mengirim header quota-project, dan memakainya butuh `serviceusage.services.use` — izin yang tidak ada di kedua role itu. Script sekarang mengikat **`roles/serviceusage.serviceUsageConsumer`** juga, dan menjalankan Python dengan `env -u GOOGLE_CLOUD_QUOTA_PROJECT` supaya headernya tidak terkirim sejak awal. Role tambahan tidak menggagalkan checkpoint Task 1 — grader mengecek keberadaan dua role lab, bukan ketiadaan yang lain.

Binding IAM butuh waktu propagasi, jadi langkah Python diulang sampai 3 kali dengan jeda 30 detik.

## Keputusan desain

### Script Python ditulis ulang, bukan ditambal

Instruksi lab menyuruh menyalin `analyze-images-v2.py` dari bucket lalu mengisi tiga bagian `# TBD:`. Script ini **tidak** melakukan itu — ia menulis `~/analyze-images-v2.py` versinya sendiri dari nol.

Alasannya: yang dilihat grader adalah hasil (file `.txt` di bucket, baris di BigQuery, query yang pernah jalan), bukan isi file `.py`. Menambal file lab berarti bergantung pada teks komentar yang bisa berubah antar-revisi lab, dan `sed`/`awk` yang meleset baru ketahuan saat sudah di dalam lab berjam. Menulis utuh menghilangkan seluruh kelas kegagalan itu.

### Kolom BigQuery dipetakan dari `table.schema`

Solusi resmi memakai `insert_rows(table, [(desc, locale, translated, filename)])` — tuple posisional, jadi urutan kolom tabel harus persis seperti yang diasumsikan. Script ini membaca `table.schema` dulu lalu membangun **dict** per baris:

- nama kolom mengandung `locale`/`lang` → locale
- mengandung `trans` → teks terjemahan (dicek sebelum aturan generik, karena `translated_text` juga mengandung `text`)
- mengandung `file`/`image`/`name` → nama file gambar
- sisanya → teks asli hasil Vision

Jadi jumlah atau urutan kolom yang berbeda antar-instance lab tidak membuat insert gagal. Nama kolom dicetak saat jalan, kalau pemetaannya salah langsung kelihatan di output.

### Virtualenv hanya kalau perlu

Cloud Shell kadang sudah membawa `google-cloud-vision`/`translate`/`bigquery`/`storage`. Script mencoba `import` dengan `python3` sistem dulu; hanya kalau gagal ia membuat `~/gsp329-env` dan `pip install`. Menghemat ~1 menit saat library sudah ada, dan menghindari PEP 668 (`externally-managed-environment`) saat belum.

### Guard tabel

`image_classification_dataset.image_text_detail` seharusnya sudah disiapkan lab setup. Script tetap membuatnya (`text,locale,translated_text,filename` semua STRING) kalau tidak ditemukan, supaya kegagalan tidak muncul di menit terakhir.

## Idempoten

Aman diulang. Service account dilewati kalau sudah ada, binding IAM idempoten, `key.json` dipakai ulang kalau filenya masih ada.

Satu efek samping: **baris BigQuery bertambah tiap run** (duplikat). Checkpoint tidak peduli — ia hanya menghitung baris per locale. Kalau ingin bersih:

```bash
bq query --use_legacy_sql=false \
  "DELETE FROM image_classification_dataset.image_text_detail WHERE true"
```

## Kalau gagal

- **`Vision API error ...`** — API belum aktif atau service account tidak punya izin memanggilnya. Script sudah `gcloud services enable vision.googleapis.com translate.googleapis.com`; tunggu ~30 detik lalu ulangi.
- **`Tidak ada gambar yang menghasilkan teks`** — bucket salah. Script mencetak daftar bucket project saat `gs://$BUCKET` tidak terbaca; ulangi dengan `BUCKET=<nama>`.
- **`Insert BigQuery gagal: [...]`** — biasanya nama kolom di luar dugaan pemetaan. Lihat baris `Kolom tabel: [...]` di output, lalu sesuaikan `build_row` di `~/analyze-images-v2.py` dan jalankan ulang hanya bagian Python:

  ```bash
  GOOGLE_APPLICATION_CREDENTIALS=~/key.json python3 ~/analyze-images-v2.py $DEVSHELL_PROJECT_ID $DEVSHELL_PROJECT_ID
  ```
- **Key creation ditolak** — kalau org policy `iam.disableServiceAccountKeyCreation` aktif, Task 2 tidak bisa diselesaikan lewat CLI. Belum pernah terjadi di lab ini.
