# GSP349 - Deploy and Manage Apigee X: Challenge Lab

Apigee eval org + Cloud Armor. Dua task via wizard/UI, tiga via API.

## Jalankan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp349.sh
bash gsp349.sh
```

Region default `us-west1` / `us-west1-c` (sesuai lab). Script menunggu org `ACTIVE` hingga 40 menit (poll `apigee.googleapis.com/v1/organizations/$ORG`). Jika baru start lab, biarkan jalan di background.

## Task

| Task | Otomatis | Catatan |
|------|----------|---------|
| 1. staging env + staging-group | Ya | `staging` (programmable, proxy) + `staging-group` host `staging.example.com` via `organizations.envgroups.create` + attachment `staging` |
| 2. Access routing (wizard step 4) | Semi | wizard `Enable internet access` > `api-subnet` > `nip.io`. Script auto-detect `eval-group` hostname `*.nip.io`; jika belum, polling 15 menit (30 iterasi x 30s) + instruksi wizard dengan box terpisah. Jika LB sudah ada tapi hostname belum nip.io, coba patch hostname dari forwarding rule IP. |
| 3. NAT apigee-nat-ip | Ya | `POST /instances/eval-instance/natAddresses {name:apigee-nat-ip}` lalu `:activate`, poll `operations/...` hingga `done` |
| 4. Cloud Armor protect-apigee | Ya | policy `protect-apigee` default allow, rule 1000 `evaluatePreconfiguredExpr('rce-stable')` `deny-403` (fallback coba `rce-v33-stable`, `rce-v422-stable`, varian Waf). Attach ke backend global Apigee (`gcloud compute backend-services update --security-policy`) |
| 5. Attach staging ke instance | Ya | `POST /instances/eval-instance/attachments {environment:staging}`, poll hingga muncul di `GET .../attachments` |

## Catatan implementasi

- **Idempoten.** Semua create cek `GET` dulu. Rule 1000 dihapus-recreate agar expression benar. NAT cek `state ACTIVE` sebelum `activate`.
- **Apigee token.** `gcloud auth print-access-token` tiap request, handle expiry.
- **Long running operation.** `wait_operation` poll `GET /v1/organizations/.../operations/<id>` sampai `done:true`.
- **Wizard vs API.** Access routing tidak ada API publik stabil; wizard membuat LB global + Google-managed cert + hostname `IP.nip.io` di `eval-group`. Script polling 15 menit untuk deteksi hostname nip.io. Jika LB sudah ada (forwarding rule) tapi hostname belum nip.io, script coba patch hostname dari IP forwarding rule. Jika wizard error `instanceTemplate does not exist`, instruksi hapus LB di `Network services > Load balancing` lalu refresh wizard.
- **Cloud Armor RCE.** Lab minta list `gcloud compute security-policies list-preconfigured-expression-sets` lalu pakai stable. Kandidat dicoba berurutan `rce-stable`, `rce-v33-stable`, `rce-v422-stable` dengan dua prefix `evaluatePreconfiguredExpr`/`evaluatePreconfiguredWaf`. Default rule diensure `allow` (2147483647).
- **Backend discovery.** Ambil `backend-services --global` yang mengandung `apigee`, fallback ke yang pertama.
- **Propagasi.** RCE `curl -k "https://IP.nip.io/hello-world?doc=/bin/ls"` butuh 2-3 menit setelah attach; checker tidak butuh block sukses.

## Yang perlu manual (jika script belum hijau)

- **Task 2** jika hostname masih `sincere-bay-...example.com` bukan `nip.io`: buka `https://apigee.google.com/setup` seperti di atas. Jika wizard redirect ke overview, berarti sudah selesai, tidak perlu klik lagi. Jika hostname belum nip.io, patch manual:
  ```bash
  LB_IP="$(gcloud compute forwarding-rules list --global --format='value(IPAddress)' | head -1)"
  curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -H "Content-Type: application/json" \
    -X PATCH "https://apigee.googleapis.com/v1/organizations/$DEVSHELL_PROJECT_ID/envgroups/eval-group?updateMask=hostnames" \
    -d "{\"hostnames\":[\"${LB_IP}.nip.io\"]}" | jq .
  ```
  Jika `curl -k -i https://IP.nip.io/hello-world` sudah `200 Hello, Guest!` tapi checker masih `Please set up access routing... If already done wait`, tunggu 5-10 menit lalu `Check my progress` 2x (propagasi Qwiklabs).
- **Task 4** jika `backend-service` tidak ditemukan: pastikan Task 2 LB sudah ada.

## Troubleshooting 2026-09-01

- **Jangan tambah health check ke PSC NEG.** `gsp349_fix_task2.sh` versi awal salah buat `apigee-health-check` lalu `gcloud compute backend-services update --health-checks`, error `A backend service cannot have a healthcheck with Private Service Connect network endpoint group backends.` Ini wajar, PSC memang tidak butuh health check. Fix: hapus orphan `gcloud compute health-checks delete apigee-health-check --global -q`, sudah diperbaiki di `gsp349_fix_task2.sh:18` jadi diagnosa murni (cleanup + cek kecocokan `LB_IP` vs `EVAL_HOST`).
- **Checker 0 poin padahal LB 200 OK.** Kasus `qwiklabs-gcp-02-01de59793956` 2026-09-01: `apigee-https-fr`+`apigee-http-fr` `8.232.4.77`, `apigee-lb-ip IN_USE`, `apigee-proxy-backend EXTERNAL_MANAGED HTTPS`, `apigee-cert ACTIVE`, `apigee-neg` `pscTargetService` sama dengan `serviceAttachment` instance, `eval-group ACTIVE ["8.232.4.77.nip.io"]`, `curl -k -i` `200 Hello, Guest!` tapi checker masih merah. Solusi tunggu propagasi, lepas-pasang Cloud Armor `protect-apigee` tidak ngaruh. `https://apigee.google.com/setup` redirect ke overview setelah selesai, jadi verifikasi lewat `gcloud compute forwarding-rules list --global` + `curl -k -i`.
- **LoadBalancingScheme.** Lab 2026 pakai `EXTERNAL_MANAGED` untuk forwarding rule dan backend. Checker lama expect `EXTERNAL` akan tetap merah meski LB jalan, cek `gcloud compute forwarding-rules describe apigee-https-fr --global --format='yaml(loadBalancingScheme)'`.
