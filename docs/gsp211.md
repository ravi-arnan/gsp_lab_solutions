# GSP211 - Create and Configure Multiple VPC Networks

Runbook untuk [`gsp211.sh`](../gsp211.sh).

Lab ini mendemonstrasikan pembuatan jaringan Custom Mode VPC, aturan firewall untuk akses ingress (SSH, ICMP, RDP), provisioning instance Compute Engine ke subnet terkait, serta konfigurasi VM multi-NIC (`vm-appliance`) yang terhubung langsung ke tiga VPC berbeda (`privatenet`, `managementnet`, dan `mynetwork`).

## Cara jalan

```bash
curl -sLO https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp211.sh
bash gsp211.sh
```

Atau one-liner:

```bash
curl -sL https://raw.githubusercontent.com/ravi-arnan/gsp_lab_solutions/main/gsp211.sh | bash
```

Script akan otomatis mendeteksi region dan zone yang digunakan oleh instance bawaan lab (`mynet-vm-1` dan `mynet-vm-2`). Jika cocok dengan panel lab, tekan Enter saat prompt konfirmasi muncul.

Lama eksekusi: ~ 2-3 menit.

## Tabel Task

| Task | Otomatis | Keterangan |
|------|----------|------------|
| 1. Create custom mode VPC networks with firewall rules | Ya | Buat VPC `managementnet` & `privatenet`, 3 subnets (`managementsubnet-1`, `privatesubnet-1`, `privatesubnet-2`), serta firewall rules allow ICMP, SSH, RDP (4 Checkpoint) |
| 2. Create VM instances | Ya | Buat VM `managementnet-vm-1` dan `privatenet-vm-1` di zone terkait (2 Checkpoint) |
| 3. Explore connectivity between VM instances | - | Latihan ping manual untuk memahami isolasi VPC internal vs external (tanpa checkpoint) |
| 4. Create VM instance with multiple network interfaces | Ya | Buat `vm-appliance` (e2-standard-4) dengan 3 NIC di `privatesubnet-1`, `managementsubnet-1`, dan `mynetwork` (Checkpoint) |

## Catatan

- **Multi-NIC Requirements**: VM dengan beberapa kartu jaringan membutuhkan mesin tipe minimal `e2-standard-4` (atau yang memiliki vCPU cukup untuk mendukung >= 3 NIC). Setiap interface wajib berada di subnet dengan rentang CIDR yang tidak saling tumpang tindih (*non-overlapping*).
- **Default Route**: Interface pertama (`nic0`) yang terpasang pada `privatenet` memegang default route internet gateway (`0.0.0.0/0 via eth0`). Interface tambahan (`nic1` dan `nic2`) hanya menerima rute ke subnet lokal masing-masing kecuali jika dikonfigurasi *policy-based routing*.
- **Idempotensi**: Script memeriksa keberadaan VPC, subnet, firewall rule, dan VM sebelum mengeksekusi perintah create, sehingga aman diulang jika koneksi terputus.
